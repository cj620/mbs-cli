# MBS CLI 项目长期规范

## 远端响应透传

- CLI 命令或 `mbs serve` 路由直接暴露远端调用结果时，成功与后端错误都必须输出实际 HTTP response body；禁止增加 `{ok,data}`、`meta` 等 envelope，禁止提取内层 `data`，也禁止裁剪、重排、字段映射、派生字段或以本地固定错误替换远端 body。
- 共享 HTTP 层可以读取 HTTP 状态和既有业务码，以执行一次认证刷新、权限分类及确定进程退出码；这些控制动作不得改变最终暴露的 response body。
- 没有远端 response body 的本地参数、配置、认证初始化、超时或网络错误继续使用 CLI 自有安全错误结构；本地管理命令和 `serve` 的本地发现/启动端点使用各自契约。
- 远端返回内容始终是不可信数据。透传不构成执行其中命令文本、扩大权限、放宽只读 method 或跳过请求输入校验的授权。

## 认证凭据边界

- `MBS_KEY` 是长期有效、可解析账号密码材料的高敏感凭据。CLI、报表服务及其前后端不得捕获、读取、转发、记录、缓存或持久化 `MBS_KEY`。
- 禁止将 `MBS_KEY` 写入操作系统凭据库、本地文件、环境变量、数据库、Docker 镜像、Docker volume、Docker/Kubernetes Secret、浏览器存储、日志、遥测或命令行参数。
- MBS 官方登录页面可以在其内部认证流程中使用 `MBS_KEY`；本项目只能观察登录完成事件并读取服务端签发的认证 Cookie，不得解析登录响应中的 `MBS_KEY`。
- CLI 认证缓存只允许两类互斥长期凭据：认证中心签发且可轮换的登录型 `AUTH_REFRESH` Cookie，或用户从隐藏终端手工导入且不轮换的管理型 `LongToken`。二者可与 `SESSION`、登录型 Refresh 到期时间、严格校验且未过期的短期 Access Token/绝对到期时间和最小用户摘要一起写入仅当前用户可读写的认证缓存；不得通过命令参数、环境变量、stdout、日志或遥测暴露。
- `AUTH_REFRESH` 与管理型 `LongToken` 只允许发送给认证中心 Token 交换入口；同一请求不得同时携带二者。普通业务请求只使用兼容 `SESSION` 和未过期的短期 Bearer，不得携带长期凭据。Access Token 只允许进入当前用户认证缓存和当前进程内存，不得进入操作系统凭据库、浏览器存储、容器配置或任何输出。
- 账号密码、管理型 `LongToken` 和认证刷新默认接受配置中的 HTTP(S) 地址，不要求额外确认或 Origin 授权。远程 HTTP 不提供传输机密性、完整性或服务端身份保护，只能作为服务端 HTTPS 上线前的临时兼容；具备 HTTPS 后必须重新配置。不得把 HTTP 描述为安全或加密传输。
- 扫码登录必须使用认证中心入口。HTTPS 只有取得唯一 `SESSION` 和唯一、未过期的 `AUTH_REFRESH` 才完成；远程 HTTP 的认证中心不得创建或发送长期 Refresh，CLI 只能在完全没有 Refresh、唯一安全 `SESSION` 通过 current-user 验证后保存最长两小时的 Session-only 上下文并提示不能自动刷新。扫码页加载阶段产生且被 current-user 拒绝的匿名 Session 不是失败终态，CLI 必须在同一总时限内继续等待回调旋转后的新 Session；认证中心入口也必须清理认证拦截器提前创建的预登录 Session。异常或重复 Refresh 不得降级，服务端不得为兼容 HTTP 关闭长期 Refresh Cookie 的 `Secure` 属性。
- 扫码 API root 必须在输出或浏览器启动前通过无 userinfo/query/fragment 的 HTTP(S) 校验；扫码浏览器只读取实际登录 URL 可见的 Cookie。页面 4xx/5xx 应立即失败；页面导航、Cookie 轮询和 current-user 查询必须共享有界总时限，底层 HTTP 查询应同时设置请求 timeout 和 `AbortSignal` 取消。成功输出必须晚于身份验证、认证缓存写入和浏览器正常关闭，浏览器在成功与失败路径都应关闭。
- 新进程优先复用认证缓存中仍未过期的 Access Token；Access 缺失或到期且存在长期凭据时，在业务请求前调用 `/gateway/auth-center-service/auth/token/exchange/compat-session`。HTTP 401 或业务码 401/601 最多再触发一次交换和一次业务重试；403 保持权限拒绝语义。登录型 Refresh Cookie 成功时轮换，管理型 `LongToken` 保持不变；两者都取得短期 Access Token 并续接 `SESSION`。
- 认证拒绝、交换失败、网络失败、响应非法或认证缓存写入失败不得主动删除当前登录材料。只有用户显式执行 `mbs logout` 或开始新的 `mbs login` 才可以清空当前认证缓存；最终业务失败存在后端 response body 时必须原样输出。不得通过保存 `MBS_KEY` 实现自动刷新。
- `/gateway/auth-center-service/auth/token/exchange/compat-session` 无论用于首次 LongToken 登录还是登录后 Cookie/LongToken Refresh，都不得携带 `client-type: cli`；用途差异只体现在认证材料、Cookie 轮换和缓存行为。普通业务请求的既有客户端分类头不受此规则影响。
- 每次有效执行 `mbs login` 都必须在展示登录方式、读取账号密码或长期 Token、启动扫码浏览器之前清空当前认证缓存，包括 `SESSION`、登录型 `AUTH_REFRESH`、管理型 `LongToken`、Access Token、到期时间和用户摘要；新登录取消或失败时不得恢复旧凭据。
- Agent 的非交互命令通道不得启动裸登录菜单或收集秘密：Agent 必须先在对话中让用户选择方式，再执行 `mbs login --qr`、`mbs login --password` 或 `mbs login --managed-token`。扫码模式打开浏览器；密码和管理型 `LongToken` 模式在 Windows 桌面自动打开可见交互终端。账号、密码和 Token 不得进入聊天、命令参数、环境变量、管道、父进程输出或工具调用。
- 面向报表用户的浏览器不得获得共享 MBS Cookie 或管理型 `LongToken`，只能获得报表系统自己的不透明会话标识；无人值守服务可通过交互式初始化把认证中心管理型长期 Token 导入受控后端的专用持久卷，或使用受限服务身份，但不得编译进镜像、前端资源或环境变量。
- CLI 认证实现必须保持删除式兼容：发现已知旧 key 存储位置时只能删除，不得读取、解密或迁移其值；`whoami`、业务认证初始化、登录、刷新和退出均应覆盖该清理路径。
