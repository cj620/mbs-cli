## 当前事实

- API/workflow 发现只允许调用后端语义召回；后端不可用时明确失败，不读取本地 manifest 或接口 Markdown 产生候选。
- 完整接口定义只通过 `mbs describe <apiId>` 从后端按需读取；仅当候选或详情包含可证明安全的 `command` 时，智能体才继续 `command --help → execute`。
- `name` 与 `domain` 是有界、无控制字符的展示元数据，不自动等同于 audit manifest 命令身份。CLI 仅在二者都符合命令标识 allowlist 时派生可选 `command`；否则省略命令且禁止猜测或转写。
- `detailCommand` 只从正整数 API ID 派生，因此中文、camelCase 或带空格的合法展示名仍可安全进入 `describe`。
- 召回与详情响应经过白名单和结构上限校验；可选 diagnostics 只输出固定分类，不包含 URL、Cookie、响应体或异常正文。
- find 本地遥测不记录自然语言 query，只保留时间、remote 模式、候选数量和可选稳定 action。
- Skill 安装使用精确替换；生成业务域只保留 `SKILL.md`，不得恢复 `skills/manifest.json` 或生成接口端点文档。

## 本地验证状态

- 当前工作区定向测试、全仓测试、构建和本地真实 `find → describe` 链路已验证；代码未提交、未推送或发布。
- 机器上的全局发布版 `mbs` 不包含当前分支命令；未在本轮覆盖全局 npm 安装。

## 演进关系

- 2026-07-23 之前的本地词法降级、`detailPath` 与接口 Markdown 方案已被后端唯一检索和后端详情替代。
- 保留业务域导航与 org/dashboard 等非接口型专用资料，不代表允许扫描本地目录发现业务接口。
- `20260806-[FEATURE]统一语义发现与数据库表召回` 在本协议上规划 table 候选与数据库只读路径；现有 find/describe 继续作为统一发现的 API 分支。
- `20260810-[BUG]修复语义发现展示名契约` 更正了“展示名必然是命令标识”的旧假设，不扩展后端公共响应。

## 当前强制约束

- 不得恢复本地接口候选或将后端失败转换为成功结果。
- 不得把后端字符串直接当作 shell/CLI 命令执行。
- 召回和详情请求只允许使用保存登录态与配置的标准 CLI 网关，不支持地址覆盖或命令行 Cookie 输入。
- 不得记录认证信息、响应正文、异常原文或用户自然语言查询。
- 发布、全局 CLI 替换和目标环境重建需要独立授权。
