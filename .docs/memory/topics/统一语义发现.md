## 当前事实

- 用户只提交自然语言，主 Skill 不要求用户判断 workflow、api 或 table。
- `mbs find` 将消费后端完成排序和权限过滤的混合候选，CLI 不建立本地接口或表向量降级。
- API 候选始终可按 ID 进入 `describe`，仅在返回安全 `command` 时继续业务命令；table 候选走 `database show-create-table → database query`，workflow 继续拆分子意图。
- 后端命令字符串不可信；table 数据源和表身份必须作为结构化参数验证和传递。
- 候选不是权限凭据，DDL 和 SQL 命令继续由后端二次鉴权和安全校验。

## 本地实现状态

- 当前工作区已扩展 find 判别联合类型，增加 table 载荷、结构化下一步动作和严格不可信响应拒绝。
- 当前工作区已更新主 Skill 与生成器的三路径协议，域级 Skill 仍无接口卡片、表卡片和 DDL。
- 当前工作区已声明 `table-actions-v1` 客户端能力，后端据此避免向旧 CLI 返回 table。
- 混合响应、动作参数安全和包级测试已完成；真实数据库只读链路、全局安装和发布物仍待验收。
- 中文/camelCase API 展示名的混合响应与详情已通过自动化和本地真实链路验证，不再导致整批发现失败。

## 演进关系

- `INTERFACE-SEMANTIC-DISCOVERY` 建立远程唯一 API/workflow find/describe。
- 本任务在该协议上加入 table 候选，不恢复本地 manifest、接口 Markdown 或词法降级。

## 当前强制约束

- CLI 不重新排序或放宽后端权限结果，不忽略未知目标类型继续执行。
- table 标识不拼接到 shell，结构详情与 SQL 查询不自动执行。
- diagnostics 和遥测不记录自然语言、DDL、SQL 行、Cookie 或未授权元数据。
- 本地 CLI、测试、Skill 源文件和文档已授权；全局安装、发布、真实服务联调和远程写入仍未授权。
