# 统一语义发现

## 记忆元信息

- **记忆键**：`UNIFIED-SEMANTIC-DISCOVERY`
- **负责模块**：`packages/cli`、`packages/doris`、`skills`
- **当前状态**：参数依赖自动解析与明确数据库目标直达已随 npm 1.1.6 发布，真实链路待验收
- **最后核验时间**：2026-09-18
- **最后核验基线**：`6f61f78dd8faf8c2b155a224314ff5219b2171b5` / `maintenance-1-v1.1.6` / npm 官方源核验
- **权威来源**：`cli-service` 同名需求；本仓库 `20260918-[FEATURE]明确数据库目标直达查询`、DEC-010、`20260909-[FEATURE]自动解析接口参数依赖`、DEC-009

## 当前事实

- 用户提交自然语言且目标未知时，主 Skill 不要求用户判断 workflow、api 或 table；首次召回直接传递用户原话，不根据本地模块关键词预判 `--domain`。
- 用户已经提供完整只读 SQL 或精确物理表身份时跳过 `mbs find`，先通过 `mbs database my-tables` 确认权限、数据源和唯一物理表；零匹配或多匹配时暂停，不回退语义召回。
- “日销表”“订单明细”等业务别名、用途描述或不唯一名称仍属于目标未知，继续执行 `mbs find`；接口发现仍必须走远端召回。
- `mbs find` 将消费后端完成排序和权限过滤的混合候选，CLI 不建立本地接口或表向量降级。
- API 候选始终可按 ID 进入 `describe`；详情证明 QUERY 后可通过公共 `mbs request` 动态查询，可选业务 `command` 仅是便利入口；table 候选走 `database show-create-table → database query`，workflow 继续拆分子意图。
- 后端命令字符串不可信；table 数据源和表身份必须作为结构化参数验证和传递。
- 候选不是权限凭据，DDL 和 SQL 命令继续由后端二次鉴权和安全校验。
- 正式语义召回必须同时经过 CLI 网关和 `cli-service` 服务层：当前分支 find 使用 `/gateway/cli/cli-service/cli/api/recall`，describe 使用 `/gateway/cli/cli-service/cli/api/recall/detail`。
- 目标 API 缺少必填参数时，npm 1.1.6 的 Agent Skill 会递归召回并执行只读来源 API；来源列表只有业务记录和目标字段都唯一时才回填，不默认取第一项。
- 首次、workflow 和参数依赖召回共享每任务最多 10 次实际 `mbs find` 预算，失败调用也计数；find、来源接口或参数值歧义以及第 11 次调用前暂停，用户决策后保留状态继续。

## 实现与发布状态

- npm 1.1.6 所在维护分支已扩展 find 判别联合类型，增加 table 载荷、结构化下一步动作和严格不可信响应拒绝。
- npm 1.1.6 已包含主 Skill 与生成器的三路径协议，域级 Skill 仍无接口卡片、表卡片和 DDL。
- npm 1.1.6 已声明 `table-actions-v1` 客户端能力，后端据此避免向旧 CLI 返回 table。
- 混合响应、动作参数安全和包级测试已完成；真实数据库只读链路仍待独立验收。
- 中文/camelCase API 展示名的混合响应与详情已通过自动化和本地真实链路验证，不再导致整批发现失败。
- npm `1.0.1` 曾使用 `/cli/cli-service`；`1.0.2` 发布了错误顺序 `/cli/gateway/cli-service`；`1.0.3` 已修正为 `/gateway/cli/cli-service`，并通过 CI、Release 与官方源安装包核验。
- Skill 生成源、7 个域级导航和 CLI 帮助已确保首次示例不带 `--domain`，并随 `1.0.2` 发布。
- 公共 `mbs request` 固定复用共享 `/gateway/cli` 和认证，危险 path 在 HTTP 前拒绝；Skill 已形成 `find → describe → request` 链路并随 `1.0.2` 发布，尚未发送真实业务请求。
- npm 1.1.6 新增 `skills/references/parameter-resolution.md`，生成器把共享入口同步到主 Skill 和 7 个域级薄导航；`mbs find` 仍保持单次远端透传，没有引入本地候选排序或 CLI 业务映射。
- 参数依赖与数据库直达协议的契约测试、生成、323 项全仓测试、14 包构建和官方包 Skill 冒烟已通过并随 npm 1.1.6 发布；未使用真实登录态、真实店铺列表、销售接口或数据库查询链路联调。
- 明确数据库目标直达协议已进入 Skill 生成器、主 Skill 和 database Skill，并随 npm 1.1.6 完成官方包核验；尚未执行真实 MBS 数据库查询。

## 演进关系

- `INTERFACE-SEMANTIC-DISCOVERY` 建立远程唯一 API/workflow find/describe。
- 本任务在该协议上加入 table 候选，不恢复本地 manifest、接口 Markdown 或词法降级。
- `DEC-009` 在既有发现和动态请求 seam 上增加 Agent 侧参数依赖编排，不改变单次 CLI 命令或后端 response body 契约。
- `DEC-010` 将 find-first 收窄为目标未知场景；明确 SQL/物理表使用现有 `my-tables → show-create-table/query` 权威链路，不改变 CLI 或后端契约。

## 当前强制约束

- CLI 不重新排序或放宽后端权限结果，不忽略未知目标类型继续执行。
- 完整只读 SQL 或精确物理表跳过 `mbs find`，但不得跳过 `my-tables`；表身份零匹配或多匹配时暂停，禁止相似表替换和语义召回兜底。
- 业务别名、用途描述和不唯一名称不得被当作精确物理表，仍进入统一语义发现。
- Agent 不得依据模块路由表或关键词在首次 `mbs find` 前添加 `--domain`。
- 同一任务不得发起第 11 次 `mbs find`；任何候选、来源记录或参数字段不能唯一确定时必须暂停等待用户决策。
- 参数来源必须通过只读 API 查询并验证，不得编造 ID、默认取列表第一项或执行后端返回的命令字符串。
- table 标识不拼接到 shell，结构详情与 SQL 查询不自动执行。
- diagnostics 和遥测不记录自然语言、DDL、SQL 行、Cookie 或未授权元数据。
- `1.0.3` 的提交、远程推送和 npm `maintenance-1` 发布已经完成；真实服务业务响应仍不得写入日志或审计文档。
