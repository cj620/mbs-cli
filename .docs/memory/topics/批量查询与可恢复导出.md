## 当前事实

- npm `maintenance-1=1.1.6` 已包含本主题的新能力；官方源版本、游标/恢复帮助与批量任务 Skill 已完成隔离验证。
- `mbs export plan` 可为 database source 保存显式 `cursor-columns`、`cursor-dialect` 和 `batch-size`；外部数据源不能省略方言。
- `mbs export run` 在数据请求前创建 task 日志、checkpoint 和 NDJSON staging 并告知路径；成功批次持久化后才推进恢复状态。
- API page/cursor 与数据库 keyset cursor 可以按最后成功批次恢复；历史无 cursor 的数据库流在已有部分结果后不宣称安全可恢复。
- 未完成任务必须显式选择 `--resume` 或 `--restart`；restart 创建新任务并保留旧证据。
- 批次默认最多额外重试三次，只覆盖暂时性传输、429 和 502/503/504；认证、权限、SQL、参数与确定性错误不重试。
- Excel 从 staging 使用 ExcelJS streaming writer 写入 `.part`，成功关闭并校验行数后发布；超出单 sheet 行数时自动拆分。
- 数据库、导出和 dashboard Skill 共享 `skills/references/bulk-task.md`，统一脚本优先、键集游标、日志先行、断点、恢复选择、有限重试和安全日志规则。

## 强制约束

- 中文/特殊标识符按数据库方言引用：Doris/MySQL 反引号，PostgreSQL 双引号；未知方言先确认。
- 大批量数据库分页必须使用稳定唯一游标，复合游标的 `WHERE` 与 `ORDER BY` 字段顺序一致。
- 所有重试和分页循环有明确上限，游标缺失、重复或不前进时停止。
- 日志不得包含 Cookie、Token、密码、完整 SQL、请求/响应正文或业务行数据。
- staging 持久化成功后才能推进 checkpoint；恢复前验证 plan 指纹并截断未提交尾部。
- XLSX 中断后不原地续写，必须从持久化 staging 重建临时 workbook。
- 真实权限拒绝立即停止，不通过换表、删字段或其他 domain 绕过。

## 深入读取条件

修改 export plan/run flags、恢复语义、checkpoint 结构、批量日志、重试分类、数据库 cursor SQL、Excel writer 或发布/回滚时，必须读取来源任务和 DEC-011。
