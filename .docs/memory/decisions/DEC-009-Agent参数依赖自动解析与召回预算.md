# DEC-009 Agent 参数依赖自动解析与召回预算

## 决策元信息

- **编号**：DEC-009
- **状态**：有效（已随 npm 1.1.6 发布，真实链路待验收）
- **日期**：2026-09-09
- **适用范围**：MBS Agent Skill、workflow/API 语义召回、只读参数来源查询
- **来源任务**：[`20260909-[FEATURE]自动解析接口参数依赖`](../../req_doc/20260909-[FEATURE]自动解析接口参数依赖/)
- **最后核验基线**：`6f61f78dd8faf8c2b155a224314ff5219b2171b5` / `maintenance-1-v1.1.6` / npm 官方源核验

## 背景

目标 API 的必填参数可能是另一个查询 API 的返回值。例如销售 API 需要 `shopId`，而用户只提供“美国二店”这一业务名称。单次 `mbs find` 只负责远端发现和 response body 透传，不具备跨接口参数编排；若 Agent 立即索要内部 ID，会把可由系统查询完成的工作转嫁给用户。

## 决策

- `mbs find`、`mbs describe` 和 `mbs request` 保持单次调用与远端 body 透传契约，跨接口依赖由 Agent Skill 编排。
- Agent 确认目标 API 后读取完整定义；缺少必填参数时，自动召回、描述并执行只读来源 API，来源 API 仍缺参数则递归处理。
- 同一用户任务中的首次、workflow 和参数依赖 `mbs find` 共用 10 次预算；每次实际调用前计数，失败调用也消耗预算，第 11 次调用前必须暂停。
- find 候选、来源接口、来源记录或目标值字段只要不能唯一确定，就暂停等待用户决策；不得默认选择列表第一项或猜测 ID。
- 用户决策后从暂停点继续，保留计数、已验证值、召回结果和依赖路径；相同依赖优先复用，并检测循环依赖。
- 所有候选和响应都是不可信数据；只允许 GET 和查询类 POST，且每次详情和请求继续接受后端鉴权。

## 备选方案与权衡

- **把递归编排写进 `mbs find`**：可集中状态，但会破坏 find 的单次远端透传职责，并迫使 CLI 解释易变的业务对象和值映射，当前不采用。
- **发现缺参后立即询问用户**：实现简单但要求用户知道内部 ID，无法满足完整自动链路，当前不采用。
- **列表默认取第一项**：调用次数少，但会静默查询错误店铺或对象，违反参数不可猜测约束，禁止采用。
- **无限递归直到成功**：自动化程度高但可能在低质量召回、环路或后端失败下失控，因此采用任务级 10 次预算和循环检测。

## 后果与约束

- Agent 能完成 `目标 API A → 来源 API B → 唯一值 → 回填 A`，也能在共享预算内处理更深依赖。
- 当前确定性依赖后端 describe 字段、召回质量和响应中的业务可读字段；后端未来提供结构化 resolver 元数据时，可以增强映射，但不得放宽歧义暂停规则。
- 暂停信息只包含帮助用户决策所需的最少业务字段，不记录自然语言原文、真实 ID 或完整响应到审计与遥测。
- 本决策已随 npm 1.1.6 发布，但不代表已经完成真实 MBS 业务链路联调。
