# DEC-001 动态查询接口使用公共只读请求命令

## 决策元信息

- **状态**：有效（QUERY/COMPUTE 扩展已随 npm 1.1.8 生效）
- **日期**：2026-08-12
- **适用范围**：`packages/cli`、MBS Skill、普通动态业务查询
- **来源任务**：`20260812-[FEATURE]新增公共只读请求命令`
- **最后核验基线**：`2b854cd` / `maintenance-1-v1.1.8` / npm `maintenance-1=latest=1.1.8`

## 背景

后端查询接口会持续新增，`find` 和 `describe` 可以动态返回接口定义，但逐接口生成并发布 CLI 命令会让执行能力滞后。所有普通接口已经统一通过 `<apiRoot>/gateway/cli/<接口路径>`，权限由网关控制。

## 决策

- 提供公开 `mbs request <GET|POST> <path>` 作为动态查询入口。
- 命令复用共享 `/gateway/cli`、Cookie、刷新和错误 envelope，不接受主机或认证覆盖。
- 仅在 `describe` 证明 `operationType=QUERY` 或 `COMPUTE`、method 为 GET/POST 且参数已确认后执行。
- 客户端拒绝可改变请求来源或掩盖路径语义的输入；网关继续执行最终权限控制。
- 可选预生成业务命令继续保留为便利入口，但不是动态接口的执行前提。
- 隐藏 `raw` 保留兼容，不作为普通 Agent 动态查询入口。

## 备选方案与权衡

- **为 cli-service 新增 invoke 接口**：可以由服务端按 ID 统一执行，但在固定网关路由和现有权限前提下增加一层接口、部署和维护成本，当前不采用。
- **继续要求预生成业务命令**：参数体验较好，但无法覆盖随时新增接口，当前仅作为稳定接口便利入口。
- **公开现有 raw**：改动最小，但 raw 接受未经公共契约保护的路径，且已有开发脚本语义不宜直接升级为普通业务入口，当前不采用。

## 后果与约束

- 新接口进入 find/describe 元数据后，无需发布新的业务命令即可查询。
- CLI 无法仅凭 HTTP POST 自证其业务语义为只读；Skill 必须检查 `operationType=QUERY` 或 `COMPUTE`，网关必须继续执行权限和操作约束。
- 请求体、Cookie、响应正文和用户自然语言不得进入日志、审计文档或遥测。

## 验证与替代

- 验证：request 输入/发送契约测试、Skill 生成协议测试、全量测试、构建和命令发现。
- 若未来网关无法可靠限制查询类 POST，需以新的后端强制校验决策替代本决策的相应安全边界；不得静默放宽 method 或 path 校验。
- 回滚：普通反向提交公共命令、Skill 和文档差异；无数据迁移或服务端状态。
