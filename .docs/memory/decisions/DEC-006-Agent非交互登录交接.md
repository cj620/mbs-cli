# DEC-006：Agent 非交互登录交接

- 状态：已随 npm `1.1.0` 发布并完成官方包核验，待真实认证联调
- 日期：2026-09-04
- 决策范围：MBS CLI 登录入口、Windows 交互终端交接、Agent Skill
- 来源任务：`20260904-[FEATURE]支持Agent对话选择登录方式`、`20260904-[RELEASE]发布1.1.0维护版本`

## 背景

Codex、Claude 等 Agent 的命令执行通道通常重定向 stdin/stdout。裸 `mbs login` 在这种通道中启动 Inquirer 后无法收到方向键和回车，最终以 `ExitPromptError` 退出。账号密码和管理型 `LongToken` 又不能进入聊天或 Agent 工具输入，因此仅增加对话式选择不足以安全收集秘密。

## 决策

1. Agent 在对话中询问用户选择扫码、账号密码或管理型长期 Token，再调用 `mbs login --qr`、`mbs login --password` 或 `mbs login --managed-token`。
2. 裸 `mbs login` 只在 stdin/stdout 都连接 TTY 时显示三选一菜单；非交互调用返回包含三个明确命令的稳定提示，不启动 Inquirer。
3. `--qr` 可从非交互 Agent 通道直接启动既有系统浏览器扫码流程。
4. `--password` 与 `--managed-token` 在非交互 Windows 桌面自动启动可见终端，并在该终端中使用隐藏输入；父进程只交接固定模式和启动路径，不接收秘密。
5. 可见终端中的子命令使用隐藏内部标记防止递归拉起，并独立验证 stdin/stdout 为 TTY。父命令等待子命令并传播成功、认证失败或其他失败。
6. 非 Windows 或无法创建交互终端时失败关闭，提示用户在本机交互终端运行已选择的明确命令；不退化为聊天、参数、环境变量或管道收集秘密。
7. 每次有效登录仍在选择方式、启动浏览器或收集秘密前清空完整认证缓存，失败或取消不恢复旧认证态。

## 权衡与后果

- 登录方式可以在不同 Agent 的普通对话中统一消歧，不依赖 MCP Elicitation、MCP App 或宿主专属控件。
- 密码和 Token 的安全输入仍依赖本机真实终端；Agent 对话本身不会获得这些秘密。
- Windows 是首个完整支持平台。macOS/Linux 暂时需要用户在本机交互终端运行明确命令。
- 父进程会等待可见终端退出，因此 Agent 工具调用在用户完成或取消登录前保持运行。
- 系统策略禁用 PowerShell、无桌面会话或窗口创建失败时，登录会保持退出状态且旧认证态已按既有规则清除。

## 被替代方案

- 在 Agent 命令通道中继续运行 Inquirer：重定向 stdin 无法可靠传递方向键和回车。
- 使用 MCP 交互或内嵌 MCP App：用户已明确要求本功能不依赖 MCP。
- 在聊天中输入账号密码或 Token：会使秘密进入模型上下文和工具记录，违反认证凭据边界。
- 将秘密放入 CLI 参数、环境变量或 stdin 管道：会扩大进程列表、日志、历史记录或父进程的暴露面。

## 验证与发布条件

- 自动化必须覆盖非交互裸登录拒绝、三个显式模式、参数互斥、防递归、终端启动失败和子进程退出码传播。
- Windows 无凭据冒烟必须证明新窗口中的 stdin/stdout 均为 TTY，且启动参数只含固定模式与内部标记。
- 发布前必须通过全仓测试、构建、CLI help、静态敏感信息检查和安装包 Skill 核验。
- 真实账号、密码、Token、Cookie 或生产响应不得进入验证证据；真实认证链路需另行使用专用测试身份联调。

## 替代关系

- 补充 DEC-004 的交互入口和跨进程秘密边界，不改变长期凭据互斥、Access Token 仅内存或登录前清理规则。
- 不替代 DEC-003；`MBS_KEY` 禁止接触和持久化的规则保持有效。
- 不改变 DEC-005 的 HTTP(S) 地址兼容决定。
