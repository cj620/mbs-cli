# DEC-011 可恢复批量任务与有界重试

## 决策元信息

- **编号**：DEC-011
- **状态**：有效（当前工作区已完成本地 V2，待发布与真实大批量链路验收）
- **日期**：2026-09-18
- **适用范围**：`packages/export`、数据库键集分页、长时间批量查询/导出/分析 Skill
- **来源任务**：[`20260918-[FEATURE]增强批量查询与可恢复导出`](../../req_doc/20260918-[FEATURE]增强批量查询与可恢复导出/)
- **最后核验基线**：`23dea9c1bf1d9a26da31dddb3825c728fe1cae08` 加当前工作区

## 背景

原 `mbs export run` 已使用 ExcelJS streaming writer，但查询结果直接进入 workbook，没有持久化批次、任务日志和恢复位置。API 分页能够逐页查询，却没有将下一页位置与已写结果形成原子断点；数据库导出只有单条服务端 NDJSON 流。网络、进程或设备中断后只能人工判断是否重跑，既可能浪费成功结果，也可能重复写入。

无限重试同样不可接受：认证层已有且仅有一次认证刷新，批量层如果不区分暂时性与确定性错误，会放大权限、SQL 或参数错误并长期占用资源。

## 决策

- 保留 `export plan → export run` 外部 seam，把批次请求、持久化、断点、日志、有限重试和 Excel 文件生命周期收敛到内部 `executeExportTask` 深模块。
- 新任务在第一次数据请求前创建独立日志、原子 checkpoint 和 NDJSON staging 文件，并向 stderr 输出任务 ID 和路径。
- 每批结果先 append + fsync 到 staging；成功后再原子推进 checkpoint。checkpoint 记录持久化字节偏移，恢复时截断未提交尾部，防止崩溃窗口产生重复行。
- API page/cursor 和显式数据库 keyset cursor 支持断点继续；未配置游标的历史数据库流只保留兼容，不宣称能够在已有部分结果后安全恢复。
- 数据库 keyset 由调用方显式提供游标列、批次大小和方言；CLI 不猜唯一键或外部数据库类型。Doris/MySQL 标识符使用反引号，PostgreSQL 使用双引号。
- 发现未完成任务时，不静默续跑或重跑。调用方必须通过 `--resume` 或 `--restart` 明确选择；restart 创建新任务并保留旧日志、中间文件和断点。
- 批次暂时性错误默认在首次失败后最多重试三次，使用有上限、带抖动的指数退避。权限、认证最终失败、SQL、参数和确定性业务错误不重试；分页批次数同样有硬上限和游标前进检查。
- Excel 不在中断文件上续写。从 staging 流式生成 `.part`，workbook 正常关闭且行数一致后才原子发布最终文件；超过单工作表行数上限时自动拆分 sheet。
- 日志只保存操作元数据、计数、耗时、安全错误分类和游标指纹，不保存凭据、完整 SQL、请求/响应正文或业务行数据。

## 备选方案与权衡

- **失败后始终全量重跑**：实现简单，但浪费成功批次且无法区分数据口径变化，不采用。
- **直接在未完成 XLSX 上续写**：XLSX 容器中断时可能没有完整中央目录，无法可靠恢复，不采用。
- **只记录行数，恢复时重新查询并跳过前 N 行**：依赖不稳定顺序且仍重复读取大量数据，不采用。
- **自动从 DDL 或列名猜测游标**：可能选到非唯一或可变字段，造成遗漏/重复，不采用。
- **所有错误统一重试**：会重复确定性失败并掩盖权限/SQL问题，不采用。
- **每个命令自行维护日志和重试**：接口浅且规则易分叉；统一到导出任务模块和共享 Skill 协议。

## 后果与约束

- `export run` 增加 task/resume/restart 和重试 flags；新行为属于待发布公共契约。
- checkpoint 保存恢复所需的游标值，但 task 日志只保存不可逆游标指纹；任务目录使用用户配置目录和受限文件权限。
- plan 指纹绑定 source 与 columns，恢复时拒绝计划漂移；过期 plan 只能恢复已启动任务，不能创建新任务。
- 普通 database NDJSON 流仍可导出，但已有部分 staging 后不能安全 resume；大批量数据库任务必须新建 cursor plan 或使用遵循共享协议的脚本。
- 本决策不改变 shared HTTP 的一次认证刷新、后端响应透传、服务端只读 SQL 安检或权限规则。
