# DEC-002 后端响应原样透传

## 决策元信息

- **编号**：DEC-002
- **状态**：有效；`find`、`describe`、`serve` 扩展已随 npm `maintenance-1=1.1.4` 发布
- **日期**：2026-08-27
- **适用范围**：所有直接暴露远端 HTTP response body 的 CLI 命令和 `serve` 远端路由
- **来源任务**：[`20260827-[FEATURE]透传后端响应内容`](../../req_doc/20260827-[FEATURE]透传后端响应内容/)、[`20260908-[FEATURE]统一透传远端响应内容`](../../req_doc/20260908-[FEATURE]统一透传远端响应内容/)
- **最后核验**：2026-09-08 / `b85c5df` / 305 项测试 + 14 包构建 + CI/Release/官方包核验

## 背景

后端普遍已返回 `{code,data,msg}` 等完整业务 body。CLI 再添加 `{ok,data}` 会形成双层 `data`；将非成功业务 `code` 转换为 `{ok:false,error}` 会丢失后端字段，增加调用者对多套错误契约的认知负担。

## 决策

- 任何直接暴露远端结果的 CLI 命令或 `serve` 路由都直接表达后端 HTTP response body，不添加 CLI envelope，不提取内层 `data`，不裁剪、重排、映射、派生或替换远端字段。
- 后端业务错误或 HTTP 错误在内部以带 body 的错误对象传播，以便保留认证刷新和进程退出码；最终 stdout 仍是后端 body。
- 无后端 response body 的本地失败继续使用 CLI 本地安全错误结构，不伪造后端内容。
- `find` 的输出路径不再归一化候选；`describe` 的公开输出与 `request --api-id` 内部元数据校验分离；`serve` 的远端路由透传 body，而本地管理端点保持自身契约。
- NDJSON 保持逐行直通；本地管理命令不伪装为远端响应。

## 备选方案与权衡

- **仅成功透传，错误继续转换**：改动小，但仍丢失后端错误字段，不满足用户决定。
- **取消所有错误分类**：最接近纯传输，但会丢失认证自动刷新与可靠进程退出码。
- **在每个生成命令修改**：能实现透传，但会扩散同一规则，降低本地性并且难以回归。

选择共享 `APIClient`/`MBSCommand` seam，在不修改生成命令的前提下一次固定错误 body、重试、输出和退出语义。

## 后果

- 下游必须直接按后端 body 契约解析，不再读取 CLI 外层 `ok/data/error/meta`。
- 后端响应 body 可能不是 JSON；文本 body 直接输出，其他值用 JSON 序列化。
- 发布属于 breaking change，必须在独立发布任务中确认版本、下游迁移、打包验收、回滚和观察。

## 验证方式

- `base-command` 契约测试覆盖 JSON、文本、后端错误 body 和本地错误。
- HTTP 客户端测试覆盖业务错误、HTTP 401/403/500、认证刷新和最终 body。
- 全量测试、构建、差异与文档一致性检查。

## 替代关系

本决策已随 npm `maintenance-1=1.0.5` 对 `MBSCommand.output()` 业务响应及后端错误生效。2026-09-08 的扩展把同一规则应用到 `find`、`describe` 和 `serve` 远端路由，并随 npm `maintenance-1=1.1.4` 发布；其他 CLI 本地输出契约继续有效。真实后端和下游迁移仍未验收。
