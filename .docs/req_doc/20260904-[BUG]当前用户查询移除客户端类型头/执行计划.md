## 风险与回滚

- 风险：`fetchCurrentUser` 同时用于 QR 登录和管理型 Token 登录，修改会影响两条获取用户摘要的路径。
- 控制：两条路径的目标接口相同且用户明确该接口不携带分类头；用函数级请求契约和登录链路回归共同锁定。
- 回滚触发：定向测试显示服务契约依赖该头，或相关认证路径出现本次引入的失败。
- 回滚步骤：恢复 `fetchCurrentUser` 的原请求头及对应测试，保留任务记录并标记回滚；无需数据和配置恢复。
- 上线观察：后续经独立授权使用专用测试身份确认两种登录的 current-user 成功率和认证失败率；本任务未执行真实联调。
