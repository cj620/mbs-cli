# 需求描述：当前用户查询移除客户端类型头

> 安全提示：本文不得记录真实账号、密码、Token、Cookie、Session ID、请求响应正文或生产内部地址。

## 任务属性

- 级别：L3（认证请求契约变化）
- 类型：BUG / SECURITY
- 记忆键：`AUTH-CREDENTIAL-BOUNDARY`
- 任务状态：已完成
- 执行授权：已授权
- 授权来源：用户明确指出当前用户查询接口也不携带 `client-type: cli`
- 交付状态：待发布
- 演进关系：部分修正 `20260904-[BUG]登录请求移除客户端类型头`

## 故障现象

首次管理型 LongToken 登录完成兼容 Session 交换后，CLI 会请求 `/gateway/auth-center-service/auth/user/current` 获取用户摘要。当前实现为该请求额外发送 `client-type: cli`，与用户确认的认证中心接口契约不一致。

## 根因分析

前一轮修复只区分了密码登录、首次 LongToken 交换和登录后 Refresh，没有把首次 Token 登录链路中的当前用户查询纳入“登录请求不发送客户端分类头”的验收范围，导致 `fetchCurrentUser` 继续沿用旧请求头。

## 业务与安全边界

本任务包含：

1. 当前用户查询只发送标准化后的 `SESSION` Cookie，不发送 `client-type`。
2. 首次 LongToken 登录仍先交换兼容 Session，再查询当前用户摘要。
3. 登录型 Refresh、管理型 LongToken Refresh 继续发送 `client-type: cli`。
4. 使用人工构造的无效占位凭据执行自动化测试，不访问真实认证服务。

本任务不包含：

- 修改密码登录、compat-session 路径、Cookie/Token 生命周期或认证缓存格式；
- 修改普通业务请求的客户端类型头；
- 使用真实账号、Token 或 Cookie 联调；
- Git 暂存、提交、推送或发布。

## 输入与输出

- 输入：compat-session 返回并经本地校验的 `SESSION` Cookie。
- 输出：当前用户查询仅携带 `Cookie: SESSION=<value>`，用户摘要解析和失败关闭行为保持不变。

## 验收标准

1. `fetchCurrentUser` 的 Axios 调用只包含 `Cookie`，不包含 `client-type`。
2. 首次 LongToken 登录的两段请求均不包含 `client-type`。
3. 两类登录后 Refresh 仍包含 `client-type: cli`。
4. 当前用户非法 Cookie、认证失败与响应校验行为不回退。
5. shared 定向测试、shared 模块测试、全仓测试和构建通过。
6. 差异和文档不包含真实凭据、调试输出或无关修改。
