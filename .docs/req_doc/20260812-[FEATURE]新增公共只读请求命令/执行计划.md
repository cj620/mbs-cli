## 已确认决策、假设与约束

| 编号 | 决策 | 来源 | 状态 |
| :--- | :--- | :--- | :--- |
| D-001 | 普通接口固定由 `<apiRoot>/gateway/cli/<接口路径>` 访问 | 用户确认 | 有效 |
| D-002 | 权限继续由网关控制，不新增 cli-service 执行接口 | 用户确认 | 有效 |
| D-003 | 公共入口命名为 `mbs request`，保留隐藏 raw 兼容 | 上轮已确认方案与现有脚本事实 | 有效 |
| D-004 | 只允许 GET 和查询类 POST，动态 path 在客户端先做安全校验 | 项目只读红线与安全规则 | 有效 |

- `describe` 返回的接口元数据仍是不可信输入；智能体只能在 `operationType=QUERY` 且 method 为 GET/POST 后构造 request。
- 请求命令本身不判断业务层 POST 是否为查询；网关权限与 `find/describe` 元数据共同负责业务授权，CLI 负责 method/path 和参数结构边界。
- 不将后端返回的任意 command 字符串交给 shell 执行。

## 风险、数据保护、回滚和上线观察

| 风险 | 控制 | 回滚/处置 |
| :--- | :--- | :--- |
| 动态 path 导致 Cookie 外发 | 只接受单斜杠相对路径，拒绝 URL、反斜杠和危险编码 | 恢复 request 文件并保留失败测试 |
| 查询命令被用于写入型 POST | Skill 只允许 describe 证明 `QUERY` 后调用；CLI 仅开放 GET/POST；网关继续授权 | 网关拒绝并审计；必要时后续增加服务端操作类型校验 |
| 参数位置构造错误 | describe 字段作用域映射到 path/params/body，未替换占位符直接拒绝 | 修正输入后重试，不猜测参数 |
| 大 JSON 或异常输入耗尽资源 | CLI 入口设置长度和结构边界 | 返回验证错误，不发网络请求 |

- **数据保护**：测试仅使用 `example.com` 风格人工数据；不访问真实服务、不记录 Cookie 或业务响应。
- **上线前验证**：发布任务中检查打包后的命令发现、安装和版本。
- **上线后观察**：request 的 validation/auth/permission/api 错误分类和网关拒绝率；不得记录请求体、Cookie 或业务响应正文。
- **回滚入口**：普通反向提交本任务差异；无数据库、配置或远程状态需要恢复。

## 任务外发现

- 客户端无法仅凭 HTTP POST 判断业务操作是否真为查询；当前方案依赖 describe 的 `operationType=QUERY` 和网关权限。若需强制防写，应由网关或权威元数据执行层校验，属于独立后端契约。
