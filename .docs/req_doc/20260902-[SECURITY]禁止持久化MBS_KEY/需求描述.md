# 需求描述：MBS 认证凭据安全与账号密码直登

> 安全提示：本文档不得记录真实账号、密码、Cookie、`MBS_KEY`、请求响应正文或内部生产地址。

## 任务属性

- 级别：L3（认证、凭据与公共认证行为）
- 类型：SECURITY / FEATURE
- 任务状态：已完成并随 npm `1.0.6` 发布，待真实联调
- 执行授权：已授权
- 授权来源：用户要求“先修改MBS_KEY和账号密码登录”
- 交付状态：已发布并完成官方源命令验证

## 背景

当前 CLI 会从浏览器请求中捕获并持久化 `MBS_KEY`，在 Cookie 缓存失效或业务请求返回认证错误时又使用该长期凭据换取新会话。`mbs login --password` 也只是打开账号密码登录页，并未提供无浏览器的终端直登。

用户已经确认：`MBS_KEY` 长期有效且可解析账号密码材料，项目必须停止捕获、读取、转发、记录和持久化；账号密码登录应在终端隐藏读取密码并直接调用认证中心登录接口。

## 业务边界

本任务包含：

1. 移除 CLI 对 `MBS_KEY` 的捕获、读取、保存和刷新依赖。
2. QR 登录只等待浏览器上下文收到 `SESSION` Cookie，不检查带 key 的请求参数。
3. `mbs login --password` 在终端读取账号和隐藏密码，通过认证中心账号密码接口直接取得 `SESSION`，不启动浏览器。
4. Cookie 失效后不自动使用长期凭据刷新；`mbs refresh` 明确要求重新登录。
5. `whoami` 不再显示 key 摘要，只报告短期会话状态和安全用户摘要。
6. 迁移代码只删除已知旧 key 存储位置，不读取或输出其中内容。

本任务不包含：

- 读取、打印或人工迁移现有 `MBS_KEY` 值；
- 使用真实账号密码或生产 Cookie 做自动化测试；
- Docker 报表系统改造、部署、发布、Git 提交或远程写入；
- 修改认证中心后端接口和网关路由。

## 输入与输出

- 输入：`mbs login --password` 后由交互式终端分别读取账号和密码；密码不得通过命令行 flag、环境变量、配置文件或 stdin 管道传入。
- 网络：仅允许向 HTTPS 认证中心发送账号密码；loopback HTTP 只用于受控本地开发代理。
- 输出：成功时保存仅含请求所需 `SESSION=<value>` 的 Cookie Header 和安全用户摘要；失败时只输出稳定的认证或配置错误，不回显凭据、Cookie 或响应正文。
- QR 登录：浏览器上下文收到 `SESSION` 后保存会话，不解析、捕获或记录 `MBS_KEY`。

## 验收标准

1. 生产代码不存在 `getKey`、`setKey`、`KEY_PARAM` 或向 `erplogin` 传 key 的逻辑。
2. 旧 key 清理实现只调用删除能力和删除已知文件，不读取文件或 Keytar 值。
3. `mbs login --password` 不调用 Playwright，密码 prompt 为隐藏输入，并向确认的认证中心路径发送 JSON `{ username, password }`。
4. 非 HTTPS 且非 loopback 的账号密码登录在发起网络请求前失败。
5. 登录只接受成功响应中的 `SESSION` Cookie，并把认证中心用户摘要转换为 CLI 安全用户信息。
6. QR 登录通过轮询浏览器 Cookie 判断成功，不读取请求 URL 中的 key。
7. Cookie 缓存失效或业务 401 不再自动刷新；`refresh` 退出码为 2 并提示重新登录。
8. `whoami` 不包含 `keyPreview`；Cookie 缓存文件按最小权限写入并只保存安全用户字段。
9. 定向测试、受影响模块回归、全仓测试、构建、帮助输出、敏感关键词检查和差异检查通过。
