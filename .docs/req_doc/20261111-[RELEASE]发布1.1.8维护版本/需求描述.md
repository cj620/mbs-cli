# 发布 1.1.8 维护版本

> 安全提示：本文不得记录 npm/GitHub 凭据、认证缓存、内部地址、真实业务响应或未脱敏生产证据。

## 任务属性

- **级别 / 类型**：L3 / RELEASE
- **任务状态**：执行中
- **交付状态**：未交付
- **记忆键**：`RELEASE-LINE-1X`、`INTERFACE-SEMANTIC-DISCOVERY`
- **发布分支**：`1.0.0`
- **目标版本**：`@mb-it-org/cli@1.1.8`
- **目标标签**：`maintenance-1-v1.1.8`
- **目标通道**：`maintenance-1=latest=1.1.8`
- **执行授权**：用户于 2026-11-11 明确要求“发布 mbs-cli 1.1.8”

## 发布目标

发布提交 `a830ba1` 中的 COMPUTE 只读接口兼容修复，使 `mbs request --api-id` 同时接受后端详情中的 `QUERY` 与 `COMPUTE`，保留真实作用类型，并继续拒绝写入类型和 PUT/PATCH/DELETE。

## 发布边界

- 只发布当前 `1.0.0` 维护线中已经提交并验证的 COMPUTE 修复及必要版本、发布文档。
- 先通过 `maintenance-1-v1.1.8` 发布精确版本并更新 `maintenance-1`，验证官方包后再提升 `latest`。
- 不修改、合并或推送 `master`，不强推、不改写历史、不覆盖旧 npm 版本。
- 不执行真实 MBS 业务查询，不读取或输出认证缓存、Token、Cookie 或业务响应正文。
- 任一构建、测试、Release、registry 或官方包验证失败时停止后续远程动作。

## 验收标准

1. 全仓测试、14 个 workspace 构建及发布守卫通过。
2. 版本提交属于 `origin/1.0.0`，维护标签唯一且精确指向该提交。
3. npm 官方源存在精确版本 `1.1.8`，`maintenance-1=latest=1.1.8`。
4. 官方包隔离安装可确认版本与 COMPUTE 详情解析修复，且写操作类型仍被拒绝。
5. 原 Bug 任务、审计索引和项目记忆与发布事实一致。

## 风险与回滚

- npm 版本不可覆盖；发布后发现问题只能以更高补丁版本修复，并可将 dist-tag 回退到已核验的 `1.1.7`。
- 标签或 Release 失败时保留失败证据，修复后重跑；不得用不同内容重建同版本。
- `latest` 只在精确版本与 `maintenance-1` 验证成功后提升。
