# 需求描述：明确数据库目标直达查询

> 安全提示：本文档不得写入凭据、真实用户数据、未脱敏日志、请求响应正文、生产数据库标识或其他敏感证据。

## 1. 背景

现行主 Skill 将所有 MBS 业务查询统一路由到 `mbs find`。当用户已经提供完整只读 SQL，或明确指定可唯一识别的物理表名时，查询目标已经确定，继续执行语义召回会增加不必要的依赖、延迟和误路由风险，并与数据库 Skill 的 `my-tables` 权限确认流程重复。

## 2. 业务边界

- 用户提供完整、可执行的只读查询 SQL 时，跳过 `mbs find`，直接进入 `mbs database` 查询流程。
- 用户明确提供物理表名或完整表身份时，跳过 `mbs find`，直接进入 `my-tables → show-create-table → query` 流程。
- “日销表”“订单明细”等业务别名、用途描述或不唯一名称仍属于目标未知，继续使用 `mbs find`。
- 直达不代表跳过鉴权、安全检查或数据源解析；每次数据库查询仍先执行 `mbs database my-tables`，并沿用其返回的 `host/database/schema/tableName`。
- 表身份不存在、无权限或不能唯一匹配时停止并提出最小消歧问题，不退回语义召回，也不猜测数据源。
- 本任务不修改 CLI 命令、后端接口、数据库权限、SQL 安检、响应格式、召回预算或参数依赖自动解析协议。

## 3. 受影响范围

- `scripts/gen-from-manifest.mjs`：主 Skill 的权威生成协议。
- `skills/SKILL.md`：生成后的主路由与消歧说明。
- `skills/references/database/SKILL.md`：数据库直达流程与边界。
- `scripts/lib/generated-skills.test.mjs`：生成契约测试。
- `.docs/memory/` 与 `.docs/req_doc/README.md`：当前事实、决策和任务索引。

## 4. 输入与输出

### 4.1 输入分类

1. 完整只读查询 SQL。
2. 可唯一识别的物理表名或完整表身份。
3. 业务别名、用途描述或普通自然语言查询目标。

### 4.2 预期输出行为

- 类型 1、2：不调用 `mbs find`，读取数据库 Skill 并执行受控数据库命令链路。
- 类型 3：调用 `mbs find`，保留 workflow/api/table 混合候选、消歧、召回预算和参数依赖协议。

## 5. 验收标准

- 主 Skill 明确声明“目标未知才语义发现，明确 SQL/物理表直达数据库”。
- 完整 SQL 与明确物理表两条路径均要求先执行 `my-tables`，禁止猜测 `host/database/schema`。
- 完整 SQL 不被强制改写为另一条语义查询；只读、显式列、`LIMIT` 等现有数据库规则保持有效。
- 明确表名但未提供 SQL 时，先读取表结构再构造查询。
- 表身份零匹配或多匹配时不调用 `mbs find` 兜底。
- 模糊业务描述仍使用原有 find-first 链路。
- 生成器、生成产物与契约测试一致；定向测试、生成 dry-run、全仓测试和构建通过。
- 未覆盖或撤销工作区中既有的参数依赖自动解析修改。
