# 需求描述：本地开发认证代理联调

> 安全提示：本文不得记录 Cookie、Session ID、账号密码、真实用户数据、未脱敏请求响应或其他敏感证据。

## 背景

Codex 调用命令时没有交互式终端，现有 `--cookie-prompt` 要求用户另开命令窗口，并且 `find`、`describe`、数据库详情与查询分别运行时需要重复输入。当前本地管理前端已经在 `http://localhost:4174/login` 使用 Vite 开发代理：Cookie 只保存在 Vite Node 进程的服务端环境中，请求携带非敏感开发模式头时由代理注入并转发到本地服务。

## 目标

1. CLI 支持通过持久化的非敏感 `devLoginUrl=http://localhost:4174/login` 复用现有开发认证代理，并允许 `MBS_DEV_LOGIN_URL` 做临时高优先级覆盖。
2. Codex 可非交互执行 `find → describe`，以及 table 候选后的 `database my-tables → schemas/show-create-table → database query` 只读流程。
3. CLI 不读取前端 `.env.local`、浏览器 Cookie、Cookie 存储或聊天中的凭据，不新增 Cookie 参数、日志或遥测。
4. 未配置开发登录 URL时，普通 CLI 登录和 `--cookie-prompt` 行为保持不变；显式 `--cookie-prompt` 优先于自动代理模式。

## 安全边界

- `MBS_DEV_LOGIN_URL` 只接受 `http` 或 `https` 的 loopback 地址，路径必须精确为 `/login`，禁止用户名、密码、查询串和片段。
- CLI 只向同一 loopback origin 的固定 `/cli/cli-service` 代理路径发送固定模式头；不得接受用户自定义代理路径或请求头。
- 开发代理模式不读取、缓存、刷新或输出 Cookie；认证失败必须直接失败，不得回退保存的普通身份。
- 仅覆盖 cli-service 驱动的语义发现、详情与数据库只读命令；不得因此扩大写操作、任意 HTTP 或其他业务服务访问范围。
- Vite 进程内是否配置 Cookie只允许检查布尔状态，不得读取或输出其值。

## 输入与输出

- 输入：非敏感 CLI 配置 `devLoginUrl`；可选环境变量 `MBS_DEV_LOGIN_URL` 具有更高优先级。
- 输出：CLI 继续使用既有结构化 JSON/NDJSON 契约；成功结果和错误中不新增 Cookie、URL 明细或代理响应正文。

## 验收标准

1. 单元测试覆盖合法 loopback、远程地址、错误路径、查询串、缺失配置和固定派生路径。
2. 单元测试证明代理模式不调用普通凭据读取和刷新，并发送固定非敏感模式头。
3. `find`、`describe`、`database my-tables`、`database schemas`、`database show-create-table` 与 `database query` 相关回归通过。
4. 构建通过，帮助与 Skill 文档说明自动代理和回退方式。
5. 本地 E2E 通过 4174 代理完成至少 `find`，并在有真实候选时继续执行对应只读详情；不得猜测 ID、表或参数。
