# 修正认证与召回地址契约

> 安全提示：本文档禁止写入 Cookie、登录密钥、真实用户数据、未脱敏请求响应和其他敏感生产证据。

## 故障现象

`1.0.0` 维护线存在三类地址偏差：

- 二维码和密码登录页通过 `withCliPathPrefix` 错误插入 `/cli`。
- npm `1.0.1` 把 find/describe 发布为 `/cli/cli-service/...`，遗漏网关层 `/gateway`。
- 历史本机配置可能把 `apiUrl` 保存为以 `/gateway` 结尾，继续参与各调用方拼接后产生重复或顺序错误。

## 根因分析

- 登录页复用了用于 CLI 路径的 `withCliPathPrefix`，但登录页属于 API 根地址下的 ERP Web 页面。
- 上一轮召回路由修复把“服务层存在”误等同于完整网关路径正确，测试和审计同时固化了缺少 `/gateway` 的结果。
- `apiUrl` 的契约是 API 根地址，但配置读写未对已知的历史 `/gateway` 后缀做兼容归一化。

## 修复预期与业务边界

- 二维码登录：`<apiRoot>/eshop/manager/login.jsp`。
- 密码登录：`<apiRoot>/eshop/manager/loginit2.jsp`。
- find：`<apiRoot>/cli/gateway/cli-service/cli/api/recall`。
- describe：`<apiRoot>/cli/gateway/cli-service/cli/api/recall/detail`。
- `apiUrl` 继续表示 API 根地址；读取和写入时把已知历史后缀 `/gateway` 归一化为根地址，不主动改写现有配置文件。
- Cookie 刷新、普通业务命令、数据库、serve、update 和 manifest 的相对路径规则保持不变，只消费归一化后的 API 根地址。
- 不修改 Cookie 内容、认证存储、请求体、响应契约、权限判断、版本号、分支历史或 npm dist-tag。

## 受影响范围

- `packages/shared/src/config.ts` 及配置测试。
- `packages/cli/src/commands/login.ts` 及登录测试。
- `packages/cli/src/find/remote-client.ts` 及 find/认证测试。
- 相关审计索引和认证、统一语义发现主题记忆。

## 输入与输出

- 输入：配置中的 API URL，允许根地址或已知历史形式 `<apiRoot>/gateway`。
- 输出：调用方统一获得不带尾斜杠和历史 `/gateway` 后缀的 API 根地址，并按各自契约追加路径。

## 验收标准

1. 登录命令的二维码和密码模式分别导航到两个确认地址，不含 `/cli` 或 `/gateway`。
2. find/describe 完整 URL 包含 `/cli/gateway/cli-service`。
3. 配置为根地址、尾斜杠地址或历史 `/gateway` 地址时均解析为同一 API 根地址。
4. Cookie 刷新、普通业务命令和其他现有路径测试不回退。
5. 定向测试、全量构建测试、差异和敏感信息检查通过。
