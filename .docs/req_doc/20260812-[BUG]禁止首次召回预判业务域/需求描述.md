# 禁止首次召回预判业务域

> 安全提示：本文档禁止写入 Cookie、登录密钥、真实用户数据、未脱敏响应正文和其他敏感生产证据。

## 背景与故障现象

`1.0.0` 长期维护线采用后端统一语义召回，首次请求应将用户原话直接交给后端判断 domain、workflow、api、table、排序和权限。然而自动生成的域级 Skill 仍要求先执行 `mbs find "<用户原始需求>" --domain <domain>`，延续了 npm `0.1.58` 的“先按关键词定位模块”思路，会在首次召回前人为缩小候选范围。

## 根因分析

- `scripts/gen-from-manifest.mjs` 的域级 Skill 模板固定添加 `--domain ${domain}`。
- `scripts/lib/generated-skills.test.mjs` 把该行为作为正确契约断言，导致生成器持续恢复旧行为。
- 根 Skill 已声明“先用用户原话执行 find”，但未明确禁止首次预判 `--domain`，与域级 Skill 形成可执行规则冲突。
- CLI 本身不推断 domain，只把调用者显式提供的 `--domain` 原样传给后端。

## 业务边界

- 首次业务语义召回必须执行 `mbs find "<用户原始需求>"`，不得根据模块关键词或域级 Skill 自动添加 `--domain`。
- 后端负责首次判断 domain、workflow/api/table、排序与权限。
- 只有用户明确限定业务域，或首次响应的 hint 建议按某个 domain 收窄时，后续请求才允许使用 `--domain`。
- 保留 `--domain` CLI 参数，不改变后端请求结构和显式过滤能力。
- 同步修改生成器、根 Skill、全部自动生成域级 Skill、CLI 帮助示例和生成契约测试。
- 本任务不修改 Cookie、认证、请求地址、错误分类、版本号，不提交、不推送、不发布 npm。

## 受影响范围

- `scripts/gen-from-manifest.mjs`
- `scripts/lib/generated-skills.test.mjs`
- `skills/SKILL.md`
- `skills/references/*/SKILL.md` 自动生成域级导航
- `packages/cli/src/commands/find.ts` 的帮助说明和示例
- 本任务审计文档、索引和统一语义发现项目记忆

## 输入与输出

- 输入：用户未经 Agent 改写的原始业务目标。
- 首次输出请求：不带 domain 过滤的统一召回请求。
- 后续输出请求：仅在用户明确限定或后端 hint 建议时携带显式 `--domain`。

## 验收标准

1. 自动生成的每个域级 Skill 首次示例不包含 `--domain`。
2. 域级 Skill 仅在用户明确限定或首次 hint 建议时展示二次 `--domain` 用法。
3. 根 Skill 明确模块路由表不得用于首次 find 前的 domain 预判。
4. CLI 帮助不再把预判 domain 的命令作为普通示例，但继续提供受条件约束的 `--domain` 参数。
5. 生成器 dry-run、生成契约测试、CLI 定向测试、构建和相关回归通过。
6. Cookie 诊断仅给出脱敏结论：find 客户端会把缓存 Cookie 设置到 Axios 请求头；不记录其值。
