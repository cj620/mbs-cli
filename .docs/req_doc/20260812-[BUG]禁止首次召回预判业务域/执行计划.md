## 执行步骤

### S1：Cookie 传递链诊断

- **状态**：已完成
- **目标**：确认 find 是否携带 Cookie，不泄露 Cookie 内容。
- **证据**：shared HTTP 13 条测试和 recall client 1 条测试通过；代码链为 `getAuthContext → createRecallClient → APIClient → axios.create(headers.Cookie)`。
- **结论**：find 会携带缓存 Cookie；HTTP 403 仍可能来自 Cookie 过期、网关策略或服务前置认证，并非“未设置 Cookie”。

### S2：新增首次 find 契约回归

- **状态**：已完成
- **目标**：让当前域级生成物因首次命令带 `--domain` 而失败。
- **验证**：修改前运行 `node --test scripts/lib/generated-skills.test.mjs` 得到 2 项预期失败；生成后 3 项全部通过。

### S3：修改生成器、Skill 与 CLI 帮助

- **状态**：已完成
- **目标**：生成首次无 domain、条件式二次收窄的统一说明。
- **验证**：重复执行 `--skill-index-only` 前后差异指纹一致；生成契约测试通过；`find --help` 的普通示例不含 `--domain`，flag 明确仅用于显式范围或 hint 后续调用。

## 任务外发现

- `mbs find` 会携带缓存 Cookie，但 Axios 的原始 HTTP 403 不会被当前 `NotAuthenticatedError` 重试路径自动刷新；Apifox 成功而 CLI 403 仍需用同一 Cookie/请求头与网关日志进一步比较。本任务不修改该行为。
- 当前错误边界把 HTTP 403统一显示为“Semantic discovery service is unavailable”，错误分类改进属于独立需求。
