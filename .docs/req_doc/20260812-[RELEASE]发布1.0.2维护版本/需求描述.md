# 发布 1.0.2 维护版本需求描述

## 背景

`1.0.0` 长期维护分支已完成三组待发布变更：首次语义召回不再由 CLI 预判业务域；登录与语义召回恢复用户确认的完整地址契约；新增公共只读 `mbs request` 命令，使后端动态新增的查询接口无需预设 CLI 命令即可执行。

## 目标

- 将 `@mb-it-org/cli` 版本从 `1.0.1` 升级到未占用的 `1.0.2`。
- 将当前维护分支变更普通提交并推送到 `origin/1.0.0`。
- 分支 CI 成功后创建轻量标签 `maintenance-1-v1.0.2`，由既有 Release 工作流发布 npm。
- 发布后确认 `maintenance-1=1.0.2`，同时 `latest` 保持 `0.1.58`。
- 通过 npm 官方源核验实际发布包版本、命令发现和关键帮助入口。

## 发布内容

1. `mbs find` 首次调用直接提交用户原话；仅显式指定 `--domain` 时才携带业务域。
2. 登录地址直达 `/eshop/manager/login.jsp` 与 `/eshop/manager/loginit2.jsp`。
3. find/describe 使用 `/cli/gateway/cli-service/cli/api/recall` 及 detail 地址。
4. 新增 `mbs request GET|POST <path>`，固定经 `/gateway/cli/{接口路径}` 发送只读请求并复用 CLI 登录态。
5. Skill 使用链路统一为 `find → describe → request`。

## 范围边界

- 只处理 `1.0.0` 长期维护分支和 npm `maintenance-1` 通道。
- 不修改、合并或推送 master，不更新 npm `latest`。
- 不强推、不删除远程引用、不覆盖已发布 npm 版本。
- 排除用户本地 `.idea/claudeCodeTabState.xml` 修改。
- 不使用真实凭据或记录真实生产响应；动态请求仍仅允许 GET 与查询类 POST。

## 验收标准

- frozen install、构建、全量测试、发布保护和代表性 CLI 帮助均通过。
- 发布提交属于 `origin/1.0.0`，对应分支 CI 成功。
- Release 工作流成功，npm 官方源存在精确版本 `1.0.2`。
- npm dist-tag 为 `maintenance-1=1.0.2`、`latest=0.1.58`。
- 官方源安装/一次性执行可发现 `request`、`find`、`describe`，版本输出为 `1.0.2`。
