# 发布 1.0.7 维护版本需求描述

> 安全提示：本文档不得记录账号、密码、Cookie、Token、真实请求正文、生产响应、签名地址或未脱敏发布日志。

## 背景

npm `maintenance-1=1.0.6` 已发布且不可覆盖。当前 `1.0.0` 长期维护分支已实现远程 HTTP 认证默认放行：账号密码、管理型长期 Refresh Token 和 compat-session 刷新接受合法 HTTP(S) API URL，不再要求确认或 Origin 授权；`MBS_KEY` 禁令与凭据持久化边界保持不变。用户明确要求发布为 `1.0.7`。

## 目标

- 将 `@mb-it-org/cli` 从 `1.0.6` 升级到未占用的 `1.0.7`。
- 补齐当前认证变更遗漏的测试、决策和审计文件，并精确提交版本与发布记录。
- 普通推送到 `origin/1.0.0`，等待对应分支 CI 成功。
- 创建并推送轻量标签 `maintenance-1-v1.0.7`，触发现有 Release 工作流发布 npm `maintenance-1`。
- 发布后确认精确版本与 dist-tag，并从 npm 官方源隔离安装验证实际产物。

## 发布内容

1. `mbs config init` 默认接受合法 HTTP 或 HTTPS API URL，不再显示远程 HTTP 确认或保存 Origin 授权字段。
2. 账号密码登录、管理型长期 Refresh Token 登录、显式刷新和业务自动刷新统一接受配置中的合法 HTTP(S) 地址。
3. 非 HTTP(S) 协议、内嵌账号密码、query 和 fragment 仍被拒绝。
4. `MBS_KEY` 禁令、长期凭据互斥、Access Token 仅内存及重新登录前清理规则保持不变。
5. 用户文档明确说明 HTTP 会明文传输密码、Token 与 Cookie，仅作 HTTPS 上线前的临时兼容。

## 范围边界

- 只处理 `1.0.0` 长期维护分支和 npm `maintenance-1` 通道。
- 不修改、合并或推送 `master`，不更新 npm `latest`。
- 不强推、不删除远程引用、不覆盖任何已发布 npm 版本。
- 不读取真实凭据，不发起真实登录或业务请求，不把 Cookie、Token 或响应正文写入审计证据。
- 已推送提交 `8c814ed` 由并发 Claude 创建并包含 `.idea/claudeCodeTabState.xml`；本任务不改写该历史，也不继续修改该 IDE 文件。

## 验收标准

- frozen install、全工作区构建和测试、发布保护、CLI 帮助、差异及敏感信息检查通过。
- 发布提交只包含当前遗漏测试、审计、版本和必要回填，且属于 `origin/1.0.0`；分支 CI 成功。
- `maintenance-1-v1.0.7` 指向已通过 CI 的维护分支提交，Release 工作流成功。
- npm 官方源存在精确版本 `1.0.7`，`maintenance-1=1.0.7`，发布前的 `latest=0.1.59` 保持不变。
- 官方源隔离安装后版本、配置、登录和刷新帮助及已发布 Skill 内容通过核验。
