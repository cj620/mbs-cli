# 接口请求体编码端到端支持

> 安全提示：本文档不得记录 Cookie、凭据、真实请求正文、上传内容、运行时文件路径或生产响应。

## 背景

`mbs find → mbs describe → mbs request` 当前只把 `--body` 解析为 JSON。cli-service 已设计请求体模式、媒体类型、字符集和字段级 multipart/form 元数据，需要由 MBS CLI 在本地安全编码后继续通过既有 `/gateway/cli` 只读链路发送。

## 业务边界

- 保持已发布 `mbs request GET|POST <path>`、认证、网关前缀和 JSON 调用兼容。
- 新增 `--api-id`，从 cli-service 权威详情读取请求体模式与字段元数据；method/path 必须与详情匹配，不能由后端字符串触发 shell 命令。
- 支持 `NONE/JSON/FORM_URLENCODED/MULTIPART/TEXT/XML/BINARY`；表单支持 `FLAT/DOT/BRACKET/JSON_STRING` 与 `explode`。`explode=false` 时对象及带子节点数组编码为一个 JSON 字符串值，标量数组编码为一个逗号连接值。
- multipart 支持普通值、Base64 二进制和本地文件，按 part 生成独立 Content-Type 与 `SOURCE_BASENAME/FIXED/OMIT` 文件名；boundary 只在运行时生成。
- `--body-file` 仅用于当前请求，文件必须是有界普通文件；内容和路径不写日志、遥测、详情、manifest 或文档。
- audit manifest、生成命令和本地 serve 路由保留并消费新元数据；旧 manifest 缺失模式时继续按“有 body schema→JSON，否则 NONE”处理。
- 继续只允许 GET 与查询类 POST；不发送真实业务请求，不修改认证、网关权限、npm 版本或发布状态。

## 输入与输出

- JSON/urlencoded/multipart：`--body` 为有界 JSON。
- TEXT/XML：`--body` 为原始文本，或通过 `--body-file` 读取字节。
- BINARY：`--body` 为严格 Base64，或通过 `--body-file` 读取字节。
- multipart FILE 字段的 JSON 值为本地路径，BINARY 字段值为严格 Base64。
- 输出继续使用现有成功/失败 envelope；输入、文件和编码错误必须在网络调用前失败。

## 验收标准

1. `describe` 保留接口级和字段级请求体元数据并对不可信响应执行枚举、长度和结构校验。
2. 七种模式、嵌套表单、重复数组、multipart 普通/文件/Base64 part、独立 Content-Type 与文件名均有自动化测试。
3. 动态 request 在 `--api-id` 下校验详情 method/path，并把编码后的 body 与 Content-Type 交给共享认证客户端。
4. 共享客户端支持受控自定义 Content-Type，不允许调用方覆盖 Cookie 或认证上下文。
5. manifest 归一化、后续生成命令和 serve 路由消费新元数据，旧 JSON manifest 行为不回退。
6. 定向测试、全量测试、构建、命令帮助、生成稳定性和敏感信息检查通过。
