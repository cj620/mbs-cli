# 需求描述：登录请求移除客户端类型头

> 安全提示：本文不得记录真实账号、密码、Token、Cookie、Session ID、请求响应正文或生产内部地址。

## 任务属性

- 级别：L3（认证请求契约变化）
- 类型：BUG / SECURITY
- 任务状态：待发布
- 执行授权：已授权
- 授权来源：用户明确要求账号密码登录和 Token 登录请求不增加 `client-type: cli`
- 交付状态：待发布；已纳入 `1.1.0` 维护发布

## 故障现象

账号密码接口使用不含 `client-type: cli` 的等价请求可以成功，但 npm `1.0.7` 的 CLI 会为密码登录请求增加该头并返回通用认证失败。首次管理型 LongToken 登录也通过共享交换函数增加同一请求头。

## 根因分析

CLI 将业务请求使用的客户端类型头扩散到了认证登录端点。认证中心确认的登录契约不包含该头，导致 CLI 请求与可成功的直接请求不等价。

## 业务与安全边界

本任务包含：

1. 账号密码登录请求不发送 `client-type: cli`。
2. 首次管理型 LongToken 登录请求不发送 `client-type: cli`，但继续只发送所需的 `Authorization: LongToken <token>`。
3. 登录后的 compat-session Refresh、当前用户查询及普通业务请求保持现有请求头契约。
4. 使用人工构造凭据完成自动化测试，不记录或重放用户提供的测试凭据。

本任务不包含：

- 修改认证中心、网关、Cookie、Token 生命周期或缓存格式；
- 修改并行进行中的 Agent 非交互登录交互实现；
- 使用真实凭据联调；本修复实施任务本身不包含发布或 Git 写入，这些动作后来由独立的 `20260904-[RELEASE]发布1.1.0维护版本` 任务获得用户明确授权并统一执行。

## 输入与输出

- 输入：终端采集的账号密码，或隐藏输入的管理型 LongToken。
- 输出：登录请求与认证中心约定一致；成功后的 Cookie、用户摘要与本地缓存行为保持不变。

## 验收标准

1. 密码登录的 Axios 调用不包含 `client-type` 请求头。
2. 首次 LongToken 登录只包含 `Authorization`，不包含 `client-type`。
3. 登录型 Refresh 和管理型 Refresh 的既有 `client-type: cli` 行为不回退。
4. 共享认证定向测试、模块测试、构建和差异检查通过。
5. 不修改或覆盖工作区中无法确认归属的并行改动。
