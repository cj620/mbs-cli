## 发布目标

将当前工作区已完成验证的三项 CLI 优化提交到 `origin/1.0.0`，并通过维护标签发布 npm 1.1.6：

1. Agent 自动解析查询接口缺失参数，在共享 10 次 `mbs find` 预算内递归发现只读参数来源，歧义或预算耗尽时暂停。
2. 用户给出完整只读 SQL 或明确物理表时跳过语义 `find`，先经 `my-tables` 确认数据源与权限，再直达数据库查询。
3. 批量查询与导出使用方言化标识符引用、键集游标分页、日志先行、原子断点、显式恢复/重启、有限指数退避和流式 XLSX。

## 发布边界

- `1.0.0` 是 1.x 长期维护分支，使用 `maintenance-1-v1.1.6` 触发 Release workflow，仅更新 npm `maintenance-1`。
- 用户表述中的“last 版本”按“当前维护线最新版本”处理；npm 默认 `latest` 保持 `0.1.59`，不得由维护标签移动。
- 2026-09-18 用户进一步明确要求将 npm `latest` 改为 `1.1.6`；该最新指令覆盖上一条对“last”的解释，但只授权移动 dist-tag，不授权重新发布包、移动 Git 标签或改写历史。
- 本次只提交当前 `mbs-cli` 工作区中可归属上述三项功能、测试、Skill、记忆、审计和版本元数据的变更。
- 不执行真实 MBS 查询，不读取或输出认证缓存、Token、Cookie、数据库凭据或业务响应正文。
- 不强推、不改写历史、不覆盖已发布 npm 版本；CI、Release 或官方包门禁失败时停止后续动作。

## 风险与回滚

- Agent Skill 变更依赖后端召回和接口说明质量；歧义时必须暂停，不能静默选择。
- 数据库键集分页要求稳定且唯一的游标列；不满足条件时必须拒绝安全恢复，不能伪装为可续传。
- npm 版本不可覆盖。若 1.1.6 发布后发现严重问题，停止推广并以更高补丁版本修复。
- 标签发布失败时保留唯一标签和失败证据，修复工作流后重跑；不得删除后用不同内容重建同版本标签。
- `latest` 提升是可逆的通道元数据变更；若需要回滚，恢复为提升前已核验的 `npm dist-tag add @mb-it-org/cli@0.1.59 latest`，不得撤销或覆盖 1.1.6 包内容。
