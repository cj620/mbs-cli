## 3. 已确认决策、假设与约束

- D-001：`name` 和 `domain` 是展示元数据，不自动等同于 audit manifest 命令身份。
- D-002：不对中文或 camelCase 做 slug 转换，因为转换结果不能证明对应 CLI 命令存在。
- D-003：保持 `command` 可选以兼容已有安全 kebab-case 候选；不扩大后端公共响应。
- D-004：API ID 是 `describe` 动作的唯一可信本地派生输入。
- 约束：不信任或执行后端命令字符串；不恢复本地发现降级；所有修改方法保持同步标准文档。

## 8. 风险、数据保护与回滚

- 风险：放宽展示文本可能误把不可信文本用于命令。控制措施是命令字段继续独立使用严格 allowlist 正则，展示文本只输出、不执行，并保留长度和控制字符限制。
- 风险：无命令的 API 候选不能直接执行业务命令。该状态比猜测命令安全；仍可 `describe`，后续需由权威 manifest 提供独立命令身份才能执行。
- 数据保护：测试使用人工构造样本；真实验证不记录请求/响应正文、认证信息或内部地址。
- 回滚：恢复本任务对解析器、类型、测试和 Skill 的局部差异即可；无数据库、配置或外部状态需要回滚。
- 上线前：需通过包级测试、构建和真实 loopback `find`。
- 上线后观察：关注 semantic-discovery 契约失败率、缺失 `command` 的 API 候选比例和 `describe` 成功率；本任务不执行发布。
