# 需求描述：修复语义发现展示名契约

> 安全提示：本文档不得记录凭据、真实用户数据、未脱敏请求响应、内部地址或生产连接信息。

## 1. 背景与故障现象

`mbs find` 已能成功请求后端统一语义发现，后端的 embedding、Milvus、权限过滤和候选查询均正常完成；当混合结果包含 API 候选时，CLI 却返回 `Semantic discovery service is unavailable`，可选诊断仅显示 `remoteFailure=unknown`。同一自然语言请求收窄为 `table` 或 `workflow` 时可以成功，收窄为 `api` 时稳定失败。

## 2. 根因分析

后端 `name` 是接口展示名称，现有数据允许中文和 camelCase。CLI 错误地把 `name` 与 `domain` 同时当作已安装业务命令的 kebab-case 标识：任一展示名称不匹配命令正则就拒绝整批响应，并把本地契约异常包装为通用依赖不可用。

同一错误假设同时存在于 `find` 和 `describe`：两处都会从展示字段伪造 `mbs <domain> <name>`。展示字段不是 audit manifest 生成的稳定命令身份，不能安全证明对应命令实际存在。

## 3. 修复预期

- API 的 `name` 与 `domain` 按有界、无控制字符的展示文本验证，不再要求 kebab-case。
- 仅当 `name` 与 `domain` 本身都是合法命令标识时，保留兼容的派生 `command`；否则省略 `command`，不得猜测、转写或执行后端命令字符串。
- `detailCommand` 始终只从正整数 API ID 派生，中文或 camelCase 展示名不得阻断 `find → describe`。
- `describe` 使用相同规则：完整只读定义仍可返回，业务 `command` 仅在命令身份可证明时出现。
- table、workflow、未知类型、字段树上限、结构化动作和只读安全边界保持不变。
- 契约或结构真正非法时仍失败默认拒绝，不恢复本地接口卡片或词法降级。

## 4. 影响范围

- `packages/cli/src/find/find-service.ts`
- `packages/cli/src/find/detail-service.ts`
- `packages/cli/src/find/types.ts`
- 对应 Vitest 测试
- 主 Skill 与生成器中的 API 候选处理说明
- 本任务审计文档、审计索引和接口语义发现记忆

不修改 `cli-service` 后端响应结构、数据库、Milvus、认证、权限、依赖、全局安装或发布配置。

## 5. 输入与输出

输入仍为后端统一语义发现及详情响应。输出保持既有 `{ok,data,meta}` envelope，API 候选的 `command` 继续是可选字段：

- 可证明安全且可映射的标识：返回兼容命令。
- 中文、camelCase、带空格等合法展示名：返回候选或详情及 `detailCommand`，省略业务 `command`。
- 控制字符、超长文本、非法结构：拒绝响应。

## 6. 验收标准

1. 包含中文和 camelCase API 展示名的混合候选可成功规范化，且不产生伪造业务命令。
2. 合法 kebab-case API 继续返回原有 `command` 和 `detailCommand`。
3. 中文 API 详情可成功返回完整只读字段树，`command` 为空。
4. 控制字符、非法 ID、写接口、未知候选类型和不一致 table 动作仍被拒绝。
5. CLI 定向测试、包级回归、全仓构建通过。
6. 原始真实命令 `mbs find "日销报表数据" --diagnostics` 不再返回语义发现不可用。
