# 发布 1.0.5 维护版本需求描述

> 安全提示：本文档不得记录凭据、Cookie、真实请求正文、生产响应、签名地址或未脱敏发布日志。

## 背景

npm `maintenance-1=1.0.4` 已发布且不可覆盖。当前 `1.0.0` 长期维护分支工作区已完成后端响应原样透传：业务查询成功或后端错误均直接输出实际 HTTP response body，不再添加 CLI `{ok,data,error}` envelope，同时保留认证刷新和非零退出码。用户确认将本次变更以新的 `1.0.5` 发布。

## 目标

- 将 `@mb-it-org/cli` 从 `1.0.4` 升级到未占用的 `1.0.5`。
- 精确提交后端响应透传功能、测试、公共契约和发布审计，普通推送到 `origin/1.0.0`。
- 维护分支 CI 成功后创建轻量标签 `maintenance-1-v1.0.5`，触发既有 Release 工作流发布 npm `maintenance-1`。
- 发布后确认 `maintenance-1=1.0.5`，同时保持发布前普通通道 `latest=0.1.59` 不变。
- 从 npm 官方源隔离核验实际发布包版本、业务成功 body 与后端错误 body 的输出契约。

## 发布内容

1. `MBSCommand.output()` 直接序列化后端 HTTP response body，不添加 CLI envelope。
2. 业务错误和 HTTP 错误携带后端 body/status 到命令边界，最终输出实际 body 并保持失败退出码。
3. 认证错误继续自动刷新一次；没有后端 body 的本地失败继续使用 CLI 安全错误结构。
4. README、Skill、项目指南、测试、记忆和重大决策同步新的公共输出契约。

## 范围边界

- 只处理 `1.0.0` 长期维护分支和 npm `maintenance-1` 通道。
- 不修改、合并或推送 `master`，不更新 npm `latest`。
- 不强推、不删除远程引用、不覆盖任何已发布 npm 版本。
- 排除用户本地 `.idea/claudeCodeTabState.xml` 修改；保留该文件本地内容且不提交。
- 不发送真实业务请求，不读取或记录凭据、Cookie 或生产 response body。
- `find`、`describe`、`serve`、本地管理命令和 NDJSON 流保持各自契约。

## 验收标准

- frozen install、manifest dry-run、全工作区构建、全量测试、发布保护、代表性编译产物 smoke、差异和敏感信息检查通过。
- 发布提交只包含已确认范围，属于 `origin/1.0.0`，对应分支 CI 成功。
- `maintenance-1-v1.0.5` 指向已通过 CI 的维护分支提交，Release 工作流成功。
- npm 官方源存在精确版本 `1.0.5`，dist-tag 为 `maintenance-1=1.0.5` 且 `latest=0.1.59`。
- 隔离安装官方包后版本、业务成功 body、后端错误 body 与退出码通过人工最小样本核验。

## 授权

用户于 2026-08-27 先要求“提交代码并发布1.0.4”，在确认该版本已占用后明确改为“发布1.0.5”。该授权包含当前范围内的版本升级、精确暂存与提交、普通推送 `origin/1.0.0`、创建并推送维护标签，以及通过既有工作流发布 npm `maintenance-1`；不包含 `master`、`latest`、强推、删除引用、覆盖已发布版本或真实业务请求。
