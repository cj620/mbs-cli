# 透传后端响应内容

> 安全提示：本文档禁止写入 Cookie、登录密钥、真实用户数据、未脱敏请求响应和其他敏感生产证据。

## 背景

当前业务查询命令将后端 HTTP body 再包装为 `{ "ok": true, "data": <body> }`。当后端本身返回 `{code,data,msg}` 时，CLI 会形成双层 `data`。后端业务错误又会被转换为本地 `{ok:false,error}`，导致原始 `code`、`data`和其他错误字段丢失。

用户明确要求：不再对后端返回内容进行 CLI envelope 封装；无论后端表达成功还是错误，输出其实际响应内容。

## 业务边界

- 使用 `MBSCommand.output()` 的业务查询命令，成功时直接输出后端 HTTP body。
- 后端在 HTTP 2xx body 中以非 `0/200` 数字 `code` 表达错误时，CLI 保留现有错误退出码与认证刷新机制，但 stdout 原样输出该 body。
- 后端以 HTTP 非 2xx 响应错误时，CLI 原样输出该 HTTP response body，并使用非零退出码。
- 认证类错误继续自动刷新一次；只有重试仍失败时才输出最后一次后端 body。
- 本地参数校验、配置、文件、认证初始化或纯网络错误没有后端 response body，继续输出 CLI 本地错误结构。
- `mbs find`/`describe` 的语义转换、`mbs serve` 的本地 HTTP 协议、本地管理命令与 NDJSON 流不在本次范围。
- 不修改只读 HTTP method 限制、路径校验、Cookie 存储、网关路由或后端协议。

## 受影响范围

- `packages/shared`：后端响应错误携带、HTTP 错误转换、CLI 原样输出及定向测试。
- `packages/_template`：业务命令模板继续调用共享输出 seam，不增加逐命令逻辑。
- `README.md`、`skills/references/global.md`与 `AGENTS.md`：同步公共输出契约。
- 当前任务审计、记忆与决策记录。

## 输入与输出

后端成功 body：

```json
{"code":200,"data":{"id":1},"msg":"ok"}
```

CLI stdout：

```json
{"code":200,"data":{"id":1},"msg":"ok"}
```

后端错误 body：

```json
{"code":1001,"data":null,"msg":"invalid request"}
```

CLI stdout 保持相同内容，退出码为 `1`。认证失败保留退出码 `2`。

## 验收标准

1. JSON、字符串、标量和 `null` 成功 body 不添加 `ok/data` envelope。
2. HTTP 2xx 内非成功业务 `code` 的完整 body 保留，且退出码不变。
3. HTTP 非 2xx response body 完整保留，401 认证刷新与最终退出码正确。
4. 没有后端 body 的本地错误仍是安全、可解析的结构化输出。
5. `request`、`raw`、预生成及兼容业务命令统一经共享 seam 获得新行为，无需逐文件修改。
6. 定向测试、共享包回归、全量测试、构建和文档一致性检查通过。
