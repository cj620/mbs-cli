# 需求描述：临时默认允许远程 HTTP 认证

> 安全提示：本文不得记录真实账号、密码、Token、Cookie、Session ID、请求响应正文、生产内部地址或其他敏感证据。

## 任务属性

- 级别：L3（认证凭据传输安全边界变化）
- 类型：SECURITY / FEATURE
- 任务状态：待验收（本地 V3 已完成，真实目标 HTTP 未联调）
- 执行授权：已授权
- 授权来源：用户先要求临时支持 HTTP，随后明确要求“默认允许 http”
- 交付状态：待发布

## 背景与最新决策

账号密码登录、管理型长期 Refresh Token 登录和 `/token/exchange/compat-session` 刷新原本只允许 HTTPS 或 loopback HTTP。本任务最初实现了远程 HTTP 的逐 Origin 显式授权，但用户最新决定是不再询问、不再保存 Origin 授权：只要配置的是合法 HTTP(S) API URL，三条认证链路均直接使用。

该变更仅调整传输门禁。`MBS_KEY` 禁令、长期凭据安全存储、Access Token 仅驻留内存、重新登录或切换用户前清理本地 Refresh Token 与 Cookie 等既有边界保持不变。

## 业务与安全边界

本任务包含：

1. `mbs config init` 接受合法的 HTTP 或 HTTPS API URL，不再对远程 HTTP 二次确认。
2. 账号密码登录、管理型长期 Refresh Token 登录、显式 `mbs refresh` 以及业务请求触发的一次性自动刷新，均可直接访问已配置的远程 HTTP 地址。
3. 配置只保存 API URL，不新增 HTTP 授权字段。
4. 继续拒绝非 HTTP(S) 协议、内嵌账号密码、查询参数和 URL fragment。
5. 错误、帮助和配置输出不得包含任何凭据或认证响应正文。
6. README、Skill 和项目安全文档必须明确：HTTP 会明文传输账号密码、Token 与 Cookie，仅为临时兼容方案。

本任务不包含：

- 修改认证中心、网关、Docker 部署或其他仓库；
- 自行设计应用层加密或绕过 TLS 的加密协议；
- 读取或发送真实账号、密码、Token、Cookie；
- 修改 `MBS_KEY` 禁令或允许其在任何位置持久化；
- Git 暂存、提交、推送、发布、部署或生产配置变更。

## 验收标准

1. 未配置额外授权字段时，合法远程 HTTP 可执行密码登录、管理型 Token 登录与 compat-session 刷新。
2. `config init` 保存 HTTP URL 时不显示确认选项卡，也不写入授权字段。
3. HTTPS 与 loopback HTTP 行为继续兼容。
4. 非 HTTP(S) 协议及含内嵌凭据、query 或 fragment 的 URL 仍被拒绝。
5. 认证缓存和 `MBS_KEY` 安全边界不变，日志和输出不泄露秘密。
6. 定向测试、全仓测试、构建、安全关键词检查和差异检查通过；真实 HTTP 凭据联调明确标记为未执行。

## 已知风险

远程 HTTP 不提供传输机密性、完整性或服务端身份认证。账号密码、长期 Refresh Token、Refresh Cookie、SESSION 和短期 Access Token 可能被链路观察者窃取或篡改；任意被配置的 HTTP 目标都将直接收到认证凭据。该风险由用户针对当前临时兼容目标明确接受，服务端具备 HTTPS 后应尽快恢复加密传输。
