# 需求描述：发布 1.1.0 维护版本

> 安全提示：本文不得记录账号、密码、Cookie、Token、真实请求正文、生产响应、签名地址或未脱敏发布日志。

## 任务属性

- 级别：L3（认证行为、跨进程登录、Git 远程写入和 npm 生产发布）
- 类型：RELEASE
- 任务状态：执行中
- 执行授权：已授权
- 授权来源：用户明确要求“提交所有未提交的代码并发布1.1.0”
- 交付状态：未交付

## 背景

当前 `1.0.0` 长期维护分支在 npm `maintenance-1=1.0.7` 基线上完成两项变更：Agent 非交互登录方式交接，以及密码登录、首次 LongToken 登录移除 `client-type: cli` 请求头。用户要求提交当前全部未提交内容并发布 `1.1.0`。

## 目标

1. 审查并提交当前工作区全部未提交改动，不遗漏两个关联任务的代码、测试、Skill、文档和记忆。
2. 将 `@mb-it-org/cli` 从 `1.0.7` 升级到未占用的 `1.1.0`。
3. 普通推送到 `origin/1.0.0`，等待分支 CI 成功。
4. 创建并推送 `maintenance-1-v1.1.0`，通过既有工作流发布 npm `maintenance-1`。
5. 发布后核验精确版本、dist-tag、官方源安装包和核心命令；保持 `latest=0.1.59` 不变。

## 发布内容

- Agent 在非交互环境先选择 `--qr`、`--password` 或 `--managed-token`；Windows 密码和 Token 模式在独立可见终端隐藏输入。
- 密码登录和首次 LongToken 登录不发送 `client-type: cli`；登录后的 Refresh 契约保持。
- `MBS_KEY` 禁令、长期凭据互斥、Access Token 仅内存、登录前清理和 HTTP 明文风险说明保持。

## 范围与安全边界

- 目标仅为 `origin/1.0.0`、标签 `maintenance-1-v1.1.0` 和 npm `maintenance-1`。
- 不修改或推送 `master`，不创建 `v1.1.0`，不移动 npm `latest`。
- 不强推、不删除远程引用、不覆盖或删除已发布 npm 版本。
- 不读取、重放、记录或提交对话中出现的凭据；真实登录验收不作为发布自动化输入。
- 发布失败时停止在可恢复状态；npm 版本不可回滚覆盖，缺陷通过更高补丁版本修复。

## 验收标准

1. 暂存差异已完整审查，不含凭据、占位实现、未说明核心缺口或无关生成物。
2. frozen install、全仓测试构建、发布保护、CLI help、差异和敏感信息检查通过。
3. 功能提交和版本提交均属于 `origin/1.0.0`，对应分支 CI 成功。
4. 维护标签精确指向版本提交，Release 工作流成功发布 npm。
5. npm 官方源存在 `1.1.0`，`maintenance-1=1.1.0`，`latest=0.1.59`。
6. 官方源隔离安装后的版本、登录帮助、Skill 和基础命令通过核验。

## 回滚与观察

- 标签推送前可通过普通修复提交纠正问题；禁止改写已推送历史。
- npm 发布后不能覆盖同版本；严重缺陷使用更高补丁版本，并在另行授权后调整 dist-tag。
- 观察分支 CI、Release 作业、npm 精确版本、dist-tags 和隔离安装结果。
