## 执行前提与安全专项

- 受保护资产：账号密码、LongToken、Refresh Cookie、SESSION、Access Token 和用户身份摘要。
- 不可信输入：配置 URL、认证响应和 Cookie；继续复用既有校验及失败关闭逻辑。
- 攻击面变化：移除认证交换接口的非必要分类头，不增加凭据类型、持久化或发送范围。
- 数据保护：测试只使用明显无效的合成值；不读取本机认证缓存，不访问真实认证服务。
- 回滚：恢复两处请求头字段和对应断言；无需数据迁移，但用户确认的服务端契约将再次不匹配。
- 上线前验证：本地 V3 后仍需独立授权在生产等价环境验证两类刷新。
- 上线后观察：compat-session 成功率、认证拒绝率、Cookie 轮换失败率；日志不得包含请求头和凭据值。

## 风险与回滚

- 风险：服务端实际部署若仍依赖该分类头，移除后两类刷新可能被拒绝；用户已明确权威接口契约，本地以请求构造测试固定，真实环境仍需独立联调。
- 风险：误删普通业务请求的客户端分类头会改变网关路由或权限；通过限定 `session-login.ts` 和 APIClient 回归控制。
- 回滚触发：目标环境验证证明 compat-session 必须携带该头，或本次引入可归因的刷新失败。
- 回滚步骤：恢复本任务源码和测试局部差异，保留审计记录并标记回滚；不修改任何凭据缓存数据。
- 数据恢复：无数据迁移；代码回滚不能恢复已轮换或已失效的凭据，失败时重新登录。
