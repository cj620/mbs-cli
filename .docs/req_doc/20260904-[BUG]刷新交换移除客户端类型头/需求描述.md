# 需求描述：刷新交换移除客户端类型头

> 安全提示：本文不得记录真实账号、密码、Token、Cookie、Session ID、请求响应正文或生产内部地址。

## 任务属性

- 级别：L3（认证请求契约变化）
- 类型：BUG / SECURITY
- 记忆键：`AUTH-CREDENTIAL-BOUNDARY`
- 任务状态：已完成
- 执行授权：已授权
- 授权来源：用户确认兼容会话交换接口不携带 `client-type: cli`、不区分 login 或 refresh，并明确要求“修改代码”
- 交付状态：待发布
- 演进关系：修正 `20260904-[BUG]登录请求移除客户端类型头` 与 `20260904-[BUG]当前用户查询移除客户端类型头` 中“登录后 Refresh 保留该头”的历史假设

## 故障现象

当前 `mbs refresh` 调用兼容会话交换接口时，登录型 Refresh Cookie 分支和管理型 LongToken 分支都会发送 `client-type: cli`。服务端接口契约明确要求该接口在 login 与 refresh 两种用途下均不携带该请求头，因此现有刷新请求与接口契约不一致。

## 根因分析

前两次请求头修复把 login 与 refresh 视为不同的客户端分类契约：首次登录移除了 `client-type`，但刷新分支通过硬编码和 `purpose === 'refresh'` 条件继续添加该头。用户本次确认同一兼容会话交换接口不按用途区分该请求头，证明该历史假设不成立。

## 业务与安全边界

本任务包含：

1. 登录型 Refresh Cookie 调用兼容会话交换接口时只发送认证所需 Cookie，不发送 `client-type`。
2. 管理型 LongToken 刷新调用同一接口时只发送 `Authorization` 和可选的兼容 `SESSION` Cookie，不发送 `client-type`。
3. 首次 LongToken 登录、密码登录和 current-user 查询继续不发送该头。
4. 同步共享认证方法文档、请求头契约测试、任务审计与认证主题记忆。
5. 测试仅使用人工构造的无效占位凭据，不访问真实认证服务。

本任务不包含：

- 修改普通业务请求使用的 `client-type: cli`；
- 修改 Cookie、LongToken、Access Token、SESSION 的生命周期、缓存格式或失败处理；
- 修改认证中心、网关、部署配置或其他仓库；
- 使用真实账号或凭据联调；
- Git 暂存、提交、推送、标签、发布或部署。

## 接口契约

- 接口：`POST /gateway/auth-center-service/auth/token/exchange/compat-session`。
- login 与 refresh 均不得携带 `client-type: cli`。
- 登录型 Refresh 使用标准化的 `SESSION` 与 `AUTH_REFRESH` Cookie。
- 管理型 LongToken 使用唯一 `Authorization: LongToken <token>`，刷新时可附带标准化的 `SESSION` Cookie。
- 请求体、响应校验、Cookie 轮换和 Access Token 仅内存边界保持不变。

## 验收标准

1. 登录型 Refresh 的 Axios 调用 headers 只包含 `Cookie`。
2. 管理型 LongToken Refresh 的 Axios 调用 headers 只包含 `Authorization` 与 `Cookie`。
3. 兼容会话交换接口的生产源码不再出现 `client-type`。
4. 普通业务 APIClient 继续携带既有 `client-type: cli`，避免扩大修改范围。
5. 认证成功、失败关闭、Cookie 轮换、Token 互斥和敏感信息边界不回退。
6. 定向测试、shared 模块测试、全仓测试、构建、差异及敏感信息检查通过。
7. 真实认证中心联调和发布状态如实标记为未执行。
