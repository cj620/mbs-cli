# 需求描述：自动解析接口参数依赖

> 安全提示：本文档不得记录凭据、真实用户数据、未脱敏请求响应、生产连接信息或可执行的远端命令文本。

## 1. 背景

当前 MBS Agent 在 `mbs find` 命中目标查询接口后，会通过 `mbs describe <apiId>` 读取完整定义；若目标接口缺少必填参数，主 Skill 仍要求直接向用户逐项追问。对于“查询美国二店销售记录”这类请求，销售接口需要 `shopId`，而该值能够通过店铺列表接口查询得到。现有流程不会稳定地继续发现、执行参数来源接口并把唯一结果回填到目标接口。

## 2. 业务目标

Agent 应在只读边界内自动完成参数依赖链：发现目标接口、读取详情、识别缺失参数、继续召回并执行参数来源接口、从返回结果中选择唯一值、回填目标参数并继续执行。只有无法唯一决策或达到召回预算时才暂停并等待用户决定。

## 3. 已确认决策

1. 同一用户任务中的 `mbs find` 最多调用 10 次，首次召回、workflow 子步骤、参数依赖召回和失败的实际调用都计数。
2. 在第 11 次调用发生前停止；不得先超限再报告。
3. 用户决策后从暂停点继续，保留已解析参数、调用轨迹和计数，不得通过暂停/恢复重置预算。
4. 缺失参数优先自动解析，不再立即要求用户提供内部 ID。
5. 参数来源接口返回列表时，唯一匹配自动回填；零匹配、多个合理匹配或字段映射不唯一时暂停。
6. `mbs find` 返回歧义或多个无法唯一选择的候选时暂停；低置信或无结果只有在后端给出唯一且不扩大原意的安全建议时才自动继续，否则暂停，不静默选择。
7. 重复依赖复用同一任务内的已验证结果；依赖环路停止，不进行无界递归。
8. `mbs find` 命令保持单次远端召回和 response body 原样透传；自动链路属于 Agent Skill 编排，不进入命令输出处理 seam。

## 4. 输入与输出

### 4.1 输入

- 用户原始业务目标及其中可识别的业务对象名称、编码、时间和范围。
- `mbs find` 返回的候选、分数与 hint。
- `mbs describe` 返回的目标接口请求字段定义。
- 参数来源接口的只读查询结果。

### 4.2 自动成功输出

- 目标接口的实际后端 response body，继续遵守原样透传契约。
- Agent 不增加 CLI envelope，不把远端命令文本作为执行授权。

### 4.3 暂停输出

暂停时向用户提供最小充分决策上下文：暂停原因、当前目标、已用/最大 `find` 次数、候选或参数值的可辨识摘要，以及需要用户选择的唯一事项。不得输出凭据、完整远端响应或未授权元数据。

## 5. 自动解析流程

1. 保存用户原始目标并初始化任务级 `find` 预算。
2. 每次调用 `mbs find` 前检查预算并立即计数。
3. 唯一确认 API 后执行 `mbs describe <apiId>`。
4. 对每个缺失必填参数，先使用用户原话、已解析上下文、字段名称和字段说明判断是否已有确定值。
5. 无确定值时，构造面向参数业务含义的后续查询，继续 `mbs find --target-type api`，不得扫描本地接口卡片或编造 API ID。
6. 唯一确认参数来源 API 后读取详情，递归补齐该接口自身的必填参数，并仅在确认 `operationType=QUERY`、GET/POST 和字段作用域后执行。
7. 从来源结果中按用户业务对象匹配值；只有结果项和目标字段均唯一时自动回填。
8. 全部参数解析完成后执行目标接口；失败时保留实际后端 response body 和既有退出语义。

## 6. 影响范围

- `scripts/gen-from-manifest.mjs`：主 Skill 与域级薄导航的生成源。
- `skills/SKILL.md`：统一发现、消歧与缺失参数处理入口。
- `skills/references/parameter-resolution.md`：自动参数依赖解析的深 Module 文档。
- `skills/references/*/SKILL.md`：由生成器同步的薄导航提示。
- `scripts/lib/generated-skills.test.mjs`：Skill 契约测试。
- `packages/cli/skills/`：构建时复制，不手工修改。
- `.docs/req_doc/`、`.docs/memory/`：任务审计与当前事实同步。

## 7. 明确不修改

- 不改变 `mbs find`、`mbs describe` 或 `mbs request` 的 CLI 参数与远端 response body 透传契约。
- 不新增写接口，不放宽 GET/查询类 POST 限制。
- 不新增本地接口卡片、manifest 检索或词法降级。
- 不修改认证、权限、Cookie、Token、网关路由或生产配置。
- 不在本任务中修改 `cli-service`、发布 npm、全局安装 Skill、暂存、提交或推送。

## 8. 验收标准

1. 主 Skill 明确缺失参数必须先自动解析，不能立即询问内部 ID。
2. 协议明确初始与后续全部 `mbs find` 共用 10 次预算，并在第 11 次前暂停。
3. 协议明确唯一候选和唯一参数值自动继续，find 歧义与参数值歧义暂停等待用户。
4. 协议明确递归依赖、结果复用、环路检测、暂停状态和预算不重置。
5. 参数来源接口仍须 `find → describe → request`，并保持只读、权限与远端内容不可信边界。
6. 生成器测试、CLI 相关测试、全仓测试、全仓构建、Skill 生成 dry-run 和帮助/Skill 冒烟通过。
7. 需求、计划、Skill、生成源、项目记忆与 Git 差异一致且不含敏感信息。
