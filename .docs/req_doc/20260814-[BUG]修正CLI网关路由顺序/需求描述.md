# 修正 CLI 网关路由顺序

> 安全提示：本文档禁止写入 Cookie、登录密钥、真实用户数据、未脱敏请求响应和其他敏感生产证据。

## 故障现象

- npm `1.0.2` 的 `mbs find` 与 `mbs describe` 把网关路径拼成 `<apiUrl>/cli/gateway/cli-service/...`，与确认的 `<apiUrl>/gateway/cli/cli-service/...` 不一致。
- audit manifest 中 13 条 action 路径以 `/gateway/<service>/...` 开头；正式业务命令已经以 `<apiUrl>/gateway/cli` 作为客户端基础地址，因此会形成 `<apiUrl>/gateway/cli/gateway/<service>/...`。

## 根因分析

- 召回客户端把 `cli` 误放在 `gateway` 之前，已有测试同步固化了错误顺序。
- 13 条 manifest action 把网关层写进了相对业务路径，违反“action path 相对于 `/gateway/cli`”的生成契约。

## 修复预期与业务边界

- find：`<apiUrl>/gateway/cli/cli-service/cli/api/recall`。
- describe：`<apiUrl>/gateway/cli/cli-service/cli/api/recall/detail`。
- 13 条 manifest action 移除开头的 `/gateway`，使正式业务命令形成 `<apiUrl>/gateway/cli/<service>/...`。
- 从源 manifest 重新生成业务包、CLI 注册及 Skill 文档，不手工编辑带 `AUTO-GENERATED FROM audit manifest` 标记的文件。
- 本修复不修改登录路径、Cookie、请求体、响应契约、权限逻辑或 `serve` 客户端基础地址；版本、提交与 npm 交付由独立的 `20260814-[RELEASE]发布1.0.3维护版本` 任务负责。

## 受影响范围

- `packages/cli/src/find/remote-client.ts` 与召回测试。
- `manifests/mbs-api-manifest.json`、生成器产物及项目 manifest 回归测试。
- 本任务审计索引与语义发现主题记忆。

## 输入与输出

- 输入：表示服务器根地址的 `apiUrl` 和相对于 CLI 网关的 action path。
- 输出：find、describe 和 13 条业务命令均按 `<apiUrl>/gateway/cli/<service>/...` 形成完整请求地址。

## 验收标准

1. find 与 describe 的完整 URL 逐字匹配确认地址。
2. 项目生成 manifest 中不存在以 `/gateway/` 开头的 action path。
3. 源 manifest 的 13 条异常路径全部变成以对应 `/<service>/` 开头，重新生成后无漂移。
4. 定向测试、全量测试、构建、生成 dry-run 和差异检查通过。
5. 不触碰用户的 `.idea/claudeCodeTabState.xml`，不执行真实业务请求；提交与发布必须遵守关联发布任务的 V3 门禁。
