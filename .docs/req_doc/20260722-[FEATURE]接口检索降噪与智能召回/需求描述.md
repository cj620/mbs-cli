# 需求描述：接口检索降噪与智能召回

> 安全提示：本文档不得记录凭据、真实用户数据、未脱敏请求响应或生产连接信息。

## 0. 2026-07-23 最新决策

用户明确要求接口发现只依赖后端语义检索，原因是本地轻量卡片缺少足够业务语义，词法降级可能返回看似成功但实际错误的候选。

- 原“后端语义召回 + 本地轻量卡片词法降级”方案已被替代。
- `mbs find` 只调用后端 `/cli/api/recall`；后端不可用、超时或响应无效时返回明确失败，不再读取本地接口卡片。
- 智能体安装物只保留主 Skill、业务域导航和非接口型专用能力文档，不再内置生成接口的轻量卡片或单接口 Markdown。
- 召回命中 API 后，通过 `mbs describe <apiId>` 从后端按需取得完整接口定义，再结合对应命令的 `--help` 确认 CLI 参数。
- 已生成的业务命令执行器继续保留；本次删除的是本地接口发现数据和端点文档，不改变已确认接口的只读执行能力。

## 1. 背景

`mbs-cli` 使用后端审计 manifest 生成 ERP 业务命令与 Claude Code skill 文档。当前 skill 层级为：主 `SKILL.md` 路由表 → 域级 `references/<domain>/SKILL.md` → 单接口端点 md。

虽然端点详情已经按需读取，但域级文档仍把域内所有 action 平铺。商品域约 925 个接口、1,878 行；Claude 路由到该域时会加载大量无关命令描述，产生上下文膨胀和选择噪声。后端 manifest 本身还包含完整字段树，不能直接作为模型接口目录。

## 2. 目标

1. 新增 `mbs find`，让 Claude 只通过后端语义召回检索少量候选。
2. 新增 `mbs describe <apiId>`，按需从后端读取召回接口的完整定义。
3. 改造生成器，将域级 skill 改成薄卡片，删除生成接口的本地卡片和单接口 Markdown；主 skill 强制 remote find-first 工作流。
4. 在不改变现有 CLI 统一成功/错误输出契约和只读边界的前提下，记录最小检索埋点，支持后续评估召回质量。

## 3. 运行流程

### 3.1 当前流程

```text
自然语言
  → Claude 读取主 SKILL.md 的模块路由表
  → Claude 读取完整域 SKILL.md
  → Claude 从大表中自行定位 action
  → Claude 读取端点 md
  → mbs <domain> <action> 执行只读查询
```

问题：第二步可能加载数百命令，与当前需求无关的描述挤占上下文。

### 3.2 改造后流程

```text
自然语言
  → Claude 执行 mbs find "原始需求或工作流 step 意图"
  → find 调用后端 recall，失败时返回明确依赖错误
  → 返回最多五个轻量 api/workflow 候选与 hint
  → Claude 选择候选；workflow 则按 steps 逐步再次 find api
  → Claude 使用 mbs describe <apiId> 从后端读取完整接口定义
  → Claude 使用候选 command --help 确认 CLI 参数
  → mbs <domain> <action> 执行只读查询
```

`mbs find` 只负责发现，不执行 ERP 写操作，也不替代已有业务命令。

## 4. 后端唯一检索模式

### 4.1 远程语义模式

调用 `POST /cli/api/recall`。返回类型：

- `api`：接口能力卡片，含 id、命令、域、描述、分数、必要参数、主要返回指标。
- `workflow`：业务工作流卡片，含名称、描述、分数、缺失条件、步骤意图。

CLI 将后端结果规范化为统一 find 输出。召回候选不携带完整字段树；确认 API 后再从后端按需读取。

### 4.2 后端接口详情模式

`mbs describe <apiId>` 调用固定的只读详情端点，返回已审核、未删除且作用类型为 `QUERY` 的接口定义。无效、不可用或非查询接口必须拒绝，不能退回本地文件或返回旧详情。

### 4.3 本地后端联调模式

开发者可通过 `MBS_RECALL_BASE_URL` 将 `mbs find` 的语义召回直接指向本机后端，跳过远程网关；未配置时保持既有网关调用路径不变。

- 配置值只允许 `http` 或 `https` 的 `localhost`、`127.0.0.1`、`::1` origin，不允许路径、查询串、片段或用户信息。
- 召回和详情路径分别固定为 `/cli/api/recall`、`/cli/api/recall/detail`，避免本地调试覆盖改变后端契约。
- 因请求会携带现有 CLI 认证 Cookie，非 loopback 地址必须拒绝，防止凭据被调试配置转发到任意主机。
- `meta.mode=remote` 表示 HTTP 语义召回成功；即使目标后端位于本机，该字段仍为 `remote`。
- 显式使用 `--diagnostics` 时，失败响应可增加安全的远程失败分类；不得包含 URL、异常正文、请求/响应体、认证信息或堆栈。默认输出不增加该字段。
- 4 秒远程超时必须取消底层 HTTP 请求，不能在命令失败后继续占用 Node 事件循环。

## 5. 异常和提示

find 必须区分：

| 场景 | 行为 |
| :--- | :--- |
| 远程成功且高置信 | 返回 top-K 候选，供 Claude 选择 |
| 远程不可达/超时 | 返回结构化依赖失败，退出码为 1，不返回本地候选 |
| 远程响应无效 | 返回结构化契约失败，不使用本地卡片掩盖问题 |
| 无候选 | 返回 `NO_RESULT` hint，提示补业务域、对象或换同义词 |
| 分数偏低 | 返回 `LOW_CONFIDENCE` hint，提示不要直接执行 |
| 候选跨域且分数接近 | 返回 `AMBIGUOUS` hint，建议确认业务域 |

错误和 hint 不能泄露认证头、cookie、请求体或接口完整响应。

## 6. 方案对比与选择

### 6.1 只拆分更多域文档

优点：改动小。

缺点：接口增长后仍会出现同一问题；跨域任务需要读多份文档；不支持自然语言检索。

结论：不作为主方案，仅把域文档改为薄卡片。

### 6.2 只用本地关键词检索（已否决）

优点：离线、无模型依赖。

缺点：无法稳定处理“销量下降原因”等用户业务语言与接口术语差异；无法召回多接口 workflow。

结论：不保留。轻量卡片无法覆盖足够业务语义，降级成功会掩盖错误候选。

### 6.3 只用后端接口向量检索

优点：对自然语言更友好。

缺点：embedding 服务或后端不可用时 CLI 失去发现能力；用户无法查询已有本地清单。

结论：采用。依赖故障必须明确暴露，由后端恢复，不再用低质量本地结果伪成功。

### 6.4 远程 find-first + 后端详情 + 薄 skill

优点：大域不再全量注入；接口事实来源唯一；在线语义召回支持业务语言和 workflow；详情始终来自后端当前数据；不破坏已有只读命令。

缺点：接口发现依赖后端、embedding 与 Milvus 可用性；需要跟随后端 API 契约演进。

结论：采用。

## 7. 输入输出指标

| 指标 | 目标 |
| :--- | :--- |
| 默认展示候选 | 最多 5 个 |
| 输出契约 | `ok/data/meta` 不变；data 为轻量候选，不含字段树 |
| 远程不可达 | 返回结构化依赖失败，不产生候选 |
| 本地后端调试 | `MBS_RECALL_BASE_URL` 仅允许 loopback origin，未配置时行为不变 |
| 大域 skill | 生成后不再平铺全部 action |
| 安装物 | 不包含生成接口卡片和生成接口单端点 Markdown |
| Claude 行为 | 必须先 find，再通过 describe 按需读取一个后端接口定义 |
| 安全边界 | 只读命令不变；find 不增加任何写操作 |
| 本地遥测 | 只记录时间、远程模式、候选数量和可选稳定 action；不记录自然语言 query、认证信息、响应体或异常正文 |

## 8. 2026-08-05 后端响应信任边界补充

- 后端返回的 `command`、`detailCommand` 不作为可信可执行字符串；CLI 必须从经过小写短横线标识校验的 `domain`、`name` 和正整数 API ID 派生固定命令。
- workflow 步骤数量必须有上限，`goal` 与 `intentQuery` 必须为非空字符串，其他字段只复制契约允许的布尔或字符串值。
- API 详情字段树必须限制深度和单层宽度，只复制执行所需字段；草稿、写接口、已删除接口由后端拒绝，CLI 仍校验 `operationType=QUERY`。

## 9. 2026-08-06 本地 Cookie Prompt

本地后端可能需要浏览器会话 Cookie，而开发者环境未必已经完成 CLI 登录。为避免把 Cookie 放进命令参数、脚本或凭据缓存，`mbs find` 与 `mbs describe` 增加显式的 `--cookie-prompt` 开关。

- 只有显式配置 `MBS_RECALL_BASE_URL`，且该值通过既有 loopback origin 校验时，才允许进入 Cookie 提示；默认网关、远程主机、带路径、查询串、片段或用户信息的地址必须在提示前拒绝。
- Cookie 使用隐藏交互提示读取，输入内容只保留在当前命令进程内，不写入 `credentials.json`、系统密钥存储、环境变量、遥测、日志、诊断信息或命令行参数。
- 输入去除首尾空白后必须非空、包含 Cookie 名值分隔符 `=`、不超过 8192 个字符，且不得包含控制字符；所有失败消息必须稳定且不得回显输入。
- 一次性 Cookie 收到未认证响应时不得回退到已保存的普通认证，也不得调用刷新流程；用户需要重新运行命令并再次输入。
- 未使用 `--cookie-prompt` 时，现有 `getAuthContext` 与刷新认证流程保持不变。
- 该开关只改变本地语义召回和详情读取的认证来源，不扩大 CLI 的只读能力，也不允许任意 HTTP 地址或写操作。

验收标准：单元测试证明回环地址限制、输入校验、隐藏提示、内存认证分支、不访问普通凭据和不刷新；帮助文档明确一次性与不持久化语义；全量测试和构建通过。真实 Cookie 不进入测试、文档或验证输出。
