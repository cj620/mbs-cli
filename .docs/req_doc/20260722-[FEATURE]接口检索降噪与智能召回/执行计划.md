## 1. 执行流程

本仓库只负责 CLI 侧接口发现与 skill 上下文控制。后端召回服务由 `cli-service` 同名功能分支提供。执行顺序：

```text
创建审计文档和索引
  → 为 find 写失败测试
  → 实现本地检索与统一结果模型
  → 为远程调用/回退写失败测试
  → 实现远程语义召回与本地降级
  → 为 skill 生成器写失败测试
  → 瘦身域级文档与更新主路由协议
  → 生成、构建、测试、在线/离线冒烟
```

每个生产代码切片均遵守“测试先失败、最小实现、测试变绿、再重构”的顺序。生成产物不直接手改，统一通过 `scripts/gen-from-manifest.mjs` 生成。

## 5. 方案选择、优缺点与约束

选择 find-first 双模式而非仅依赖 Markdown、仅本地检索或仅远程向量检索：远程语义召回解决自然语言与接口描述不一致及多接口 workflow 场景；本地词法索引防止后端/embedding 故障导致完全不可用；薄 skill 结构从根源避免大域文档全量进入上下文。

优点：上下文规模稳定、可在线语义检索、可离线降级、端点详情仍准确、保留只读安全边界。

缺点：本地与远程必须保持输出同构；本地词法不能完全替代语义；工作流质量依赖后端人工维护。通过共享结果类型、契约测试和后端 eval 集降低风险。
