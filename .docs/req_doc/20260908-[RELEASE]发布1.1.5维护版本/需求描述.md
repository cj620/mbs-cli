## 发布目标

将 `20260908-[BUG]修复业务500认证误判并定位SESSION丢失` 中属于 mbs-cli 的修复提交到 `origin/1.0.0`，并通过维护标签发布 npm 1.1.5：

- 普通业务 `code=500` 保持 `MBSError`，不再触发认证凭据交换和业务重试；
- HTTP 401 与业务 401/601 的一次刷新契约、403 权限分类及后端 response body 透传保持不变；
- 同步发布相关测试、任务审计和认证边界记忆。

## 发布边界

- 只更新 npm `maintenance-1`，`latest` 必须保持发布前的 `0.1.59`。
- 维护线通过 `maintenance-1-v1.1.5` 标签触发现有 Release workflow，不使用只支持 `master`/`latest` 的根发布脚本。
- 本次只提交 `D:\workspace\mbs-cli` 的可归属变更；不提交或发布 `technical-center`、`ingroup-erp` 的修改。
- 不读取或输出真实认证缓存、Token、Cookie、Session ID 或业务响应正文。
- 不强推、不改写历史、不覆盖已发布 npm 版本；CI 或 Release 任一门禁失败时停止后续动作。
- 发布 CLI 只能修正客户端错误分类，不代表远端 legacy ERP 的 Session 运行态已经修复。

1. 当前差异全部归属于业务 500 认证误判修复、本发布审计和必要版本元数据。
2. frozen install、全仓 306 项测试、14 包构建、发布守卫、CLI/Skill smoke、包内容和敏感信息检查通过。

## 风险与回滚

- 若某个旧后端错误地使用 500 表示登录失效，1.1.5 不再为其刷新；服务端必须迁移到现行 HTTP 401 或业务 401/601 契约。
- npm 版本不可覆盖。若 1.1.5 发布后发现严重问题，停止推广并以更高补丁版本修复。
- 标签发布失败时保留唯一标签和失败证据，修复工作流后重跑；不得删除后重建不同内容的同版本标签。
