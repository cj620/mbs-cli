# 修复语义召回服务路由

> 安全提示：本文档禁止写入凭据、真实用户数据、未脱敏日志、请求响应正文和敏感生产证据。

## 背景

`1.0.0` 维护线中的 `mbs find` 与 `mbs describe` 将语义召回请求发送到 `/gateway/cli/cli/api/...`。后端 `cli-service` 的正式网关契约包含服务层，正确前缀为 `/cli/cli-service`，因此当前地址缺少 `cli-service`，无法到达召回控制器。

## 根因

- 专用召回客户端在 `packages/cli/src/find/remote-client.ts` 中错误地把 `/gateway/cli` 作为基础路径。
- `find` 与 `describe` 的相对路径 `/cli/api/recall`、`/cli/api/recall/detail` 本身与后端控制器一致。
- 既有测试只断言了错误的基础路径，没有验证最终完整请求地址，导致回归未被发现。

## 业务边界

- 将语义召回专用客户端基础路径改为 `/cli/cli-service`。
- `mbs find` 的完整地址必须为 `/cli/cli-service/cli/api/recall`。
- `mbs describe` 的完整地址必须为 `/cli/cli-service/cli/api/recall/detail`。
- 保留现有认证、请求方法、请求体、响应解析、超时和只读边界。
- 将 `@mb-it-org/cli` 从 `1.0.0` 升级为补丁版本 `1.0.1`。
- 提交并推送 `origin/1.0.0`，待分支 CI 通过后以 `maintenance-1-v1.0.1` 发布 npm `maintenance-1`。
- npm `latest` 必须保持 `0.1.58`；不修改或合并 master，不强制推送，不弃用已发布的 `1.0.0`。

## 受影响范围

- `packages/cli/src/find/remote-client.ts`
- 语义召回相关测试
- `packages/cli/package.json`
- 本任务审计文档、审计索引和项目记忆
- `origin/1.0.0`、维护发布标签和 npm `maintenance-1` dist-tag

## 验收标准

1. 自动化测试直接断言 find 与 describe 的最终完整路径包含 `/cli/cli-service`。
2. 召回客户端继续使用保存的 CLI 认证状态，不引入本地代理、地址覆盖或新凭据读取。
3. 全 workspace 构建、测试、发布保护和代表性 CLI 帮助验证通过。
4. `packages/cli/package.json` 的版本为 `1.0.1`，没有无关依赖或锁文件变化。
5. 分支提交经普通推送进入 `origin/1.0.0`，远程 CI 成功后才创建维护标签。
6. npm `@mb-it-org/cli@1.0.1` 发布成功，`maintenance-1=1.0.1`，`latest=0.1.58`。
7. 发布包可从 npm 官方源独立执行，版本与语义发现帮助命令正常。
