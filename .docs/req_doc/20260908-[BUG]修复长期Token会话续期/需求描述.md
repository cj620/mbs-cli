# 需求描述：修复长期 Token 会话续期

> 安全提示：本文不得记录真实账号、密码、Token、Cookie、Session ID、请求响应正文、生产地址或未脱敏日志。

- 类型：BUG / SECURITY

## 背景

管理型 `LongToken` 登录会通过 `/gateway/auth-center-service/auth/token/exchange/compat-session`
取得兼容 `SESSION` 和短期 Access Token。当前实现只持久化 `SESSION`、长期凭据和安全用户摘要，
Access Token 仅存在于登录或刷新进程内。后续 CLI 进程首发请求只携带 `SESSION`；只有服务端返回
HTTP 401 或业务码 601 时才触发一次长期凭据交换。若陈旧 `SESSION` 被服务端归类为 403，CLI
会按权限错误直接结束，不会申请 Access Token。用户重新登录后因 `SESSION` 更新而恢复。

本任务部分替代 DEC-004 的 Access Token 仅内存和认证拒绝清缓存规则；`MBS_KEY` 禁止接触、
两类长期凭据互斥、长期凭据只发送认证中心、普通业务请求只使用 `SESSION`/Bearer 等边界保持不变。

## 故障现象

1. 管理型 `LongToken` 登录经过较长时间后，CLI 可能继续使用陈旧 `SESSION`，却没有主动申请可用 Access Token。
2. 业务接口返回 401/601 时可进入一次刷新，但刷新拒绝或持久化异常会清除完整认证缓存，导致长期凭据和登录信息丢失。
3. 登录阶段已取得的 Access Token 被丢弃；新 CLI 进程、终端会话或电脑重启后无法复用尚未过期的 Access Token。

## 根因分析

1. `loginWithManagedLongToken()` 内部取得 Access Token，但返回的 `AuthContext` 有意省略该字段。
2. `AuthContext` 和磁盘认证缓存不包含 Access Token；`createRecallClient()`、`MBSCommand.init()` 与
   `mbs serve` 初始化客户端时只传入 `SESSION`。
3. `forceRefreshAuthContext()` 在缺少可刷新凭据、认证中心拒绝或刷新结果落盘失败时调用
   `clearCookie()`，超出“仅显式退出或重新登录可以清空”的新契约。
4. `APIClient` 只对 `NotAuthenticatedError` 执行一次刷新；HTTP 401、业务码 401/601 属于该类型，
   403 属于 `PermissionError`。这一分类本身应保留，避免把真实无权限误判为登录过期。
5. 当前没有覆盖“持久 Access Token、缺失/到期时请求前换取、刷新失败保留登录材料”的完整回归测试。

## 已确认业务与安全边界

本任务包含：

1. 任何认证失败、刷新拒绝、网络失败、后端 401/601 或缓存写入失败，都不得隐式删除当前
   `SESSION`、`AUTH_REFRESH`、管理型 `LongToken`、Access Token、到期信息或安全用户摘要。
2. 只有用户显式执行 `mbs logout` 或开始新的 `mbs login`，才允许清空当前认证缓存。
3. 业务请求遇到 HTTP 401 或业务码 401/601 时，使用现有长期凭据申请一次 Access Token，更新认证状态并最多重试一次。
4. 交换明确拒绝长期凭据时，判定当前登录可能过期，但仍保留磁盘登录材料；显式 `mbs refresh`
   返回安全认证提示，业务请求优先展示其实际后端 response body。
5. HTTP/业务 403 继续表示权限拒绝，不因本任务自动刷新；最终存在后端 response body 时必须原样输出。
6. Access Token 与绝对到期时间允许写入现有仅当前用户可读写的认证缓存，不进入 stdout、日志、
   遥测、命令参数、环境变量、异常消息或审计证据。
7. 已过期、格式非法、字段不完整或无匹配长期凭据的磁盘 Access Token 不得用于请求，但不得使其余登录上下文失效或被删除。
8. 现有缓存不需要迁移；新增字段必须可选，旧版本应能忽略，当前版本应能读取旧缓存并在需要时申请 Access Token。
9. `MBS_KEY` 删除式兼容仍然有效；删除已知旧 `MBS_KEY` 存储不属于清空当前认证缓存。

本任务不包含：

- 修改认证中心、网关、RBAC 权限或 401/403 服务端分类；
- 读取、回显、重放或记录任何真实凭据和生产响应；
- 将 `AUTH_REFRESH` 或管理型 `LongToken` 发送给普通业务接口；
- Git 暂存、提交、推送、发布、部署或远程配置写入；
- 覆盖当前工作区中其他任务的远端响应透传修改。

## 已确认重启语义

采用方案 A：终端会话变化或电脑重启后，磁盘 Access Token 尚未到期时直接复用；缺失或到期时才用长期凭据申请。

## 输入与输出

- 输入：旧版或新版认证缓存、人工构造的有效/到期/非法 Access Token、HTTP 401/403、业务码 401/601、刷新成功/拒绝/网络失败。
- 输出：有效 Access Token 随普通业务请求作为 Bearer 使用；缺失或到期时由长期凭据换取并安全落盘。
- 输出：认证或刷新最终失败时不清空登录材料；有后端 response body 的业务请求原样输出该 body 并使用既有非零退出码。

## 验收标准

1. 管理型 `LongToken` 初次登录保存 `SESSION`、长期 Token、Access Token、Access 到期时间和安全用户摘要，缓存权限保持仅当前用户可读写。
2. 登录型 `AUTH_REFRESH` 刷新和管理型 `LongToken` 刷新都保存新 Access Token；前者继续轮换 Refresh Cookie，后者继续保留原长期 Token。
3. 新 CLI 进程使用未过期磁盘 Access Token 发出首个业务请求；Token 缺失或到期且存在长期凭据时，在业务请求前完成一次交换。
4. HTTP 401 或业务码 401/601 最多触发一次交换和一次业务重试；重试后的实际后端错误原样输出。
5. HTTP/业务 403 不触发长期凭据交换，实际后端 response body 原样输出。
6. 长期凭据被认证中心拒绝、交换响应非法、网络失败或缓存写入失败时，认证缓存文件及其中现有登录材料不被主动删除。
7. 只有显式 `mbs login` 和 `mbs logout` 的测试允许调用当前认证缓存清理；其他认证与业务路径不得调用。
8. Access Token 非法、过期或字段不完整时不进入 Authorization 头，长期凭据和用户摘要仍可读取。
9. 定向认证测试、受影响模块回归、全仓测试、14 包构建、敏感信息扫描、任务文档和差异检查通过；真实凭据联调未执行时明确披露。
