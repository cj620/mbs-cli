## 风险与回滚

| 风险 | 影响 | 控制 | 回滚 |
| :--- | :--- | :--- | :--- |
| 固定版本名分支后续维护语义不清 | 发布 1.0.1 后分支名仍为 1.0.0 | 文档明确它是长期线，不自动改名 | 后续经用户授权迁移为 `release/1.x` |
| 误触 master 发布脚本 | 覆盖 master 或创建错误标签 | 禁止运行 `pnpm release:*`，只执行精确 Git 命令 | 推送前核对 refspec；未推送前停止并恢复本地分支名 |
| 分支推送后 CI 失败 | 远程存在未通过分支 | 本地先完成 V3；CI 失败时保留分支并修复，不删除或强推 | 新增修复提交；必要时停止使用该分支 |
| 版本 1.0.0 被误认为 npm 已发布 | 用户安装预期错误 | 文档和交付明确“仅 Git 分支，npm 未发布” | 完成独立发布流程前不创建标签 |
| 维护发布意外移动 `latest` | 普通安装用户获取不同架构版本 | 发布命令始终显式 `--tag maintenance-1`，发布前后读取 dist-tags | 若未发布则停止；若已错误移动，立即停止并请求修复 `latest` 的独立授权 |
| 标签从错误分支触发 | 发布错误代码或版本 | 工作流校验标签模式、包版本和提交属于对应远程分支历史 | 工作流失败且不执行 npm publish |
| 维护用户运行 `mbs update` | 从维护线切换回 npm `latest` | README 明确维护用户使用显式 `@maintenance-1` 安装更新 | 重新安装 `@mb-it-org/cli@maintenance-1` |
