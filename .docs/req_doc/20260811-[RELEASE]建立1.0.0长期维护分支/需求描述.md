# 建立 1.0.0 长期维护分支

> 安全提示：本文档禁止写入凭据、真实用户数据、未脱敏日志、请求响应正文和敏感生产证据。

## 背景

当前 `20260722-FEATURE-接口检索降噪` 分支与 master 已形成两套不同的 manifest、业务插件和接口发现架构。继续直接合并会产生公共命令、生成数据、Skill 文档和 workspace 依赖冲突。用户决定将当前分支建立为独立的 `1.0.0` 长期维护线，不与 master 合并。

## 业务边界

- 将当前本地分支直接改名为 `1.0.0`。
- 将 `@mb-it-org/cli` 版本从 `0.1.56` 更新为 `1.0.0`。
- 让现有 CI 在 `1.0.0` 分支的 push 和 pull request 上运行。
- 完成本地 V3 验证后提交并推送 `origin/1.0.0`。
- 使用 Git 标签 `maintenance-1-v1.0.0` 触发维护线发布，将 `@mb-it-org/cli@1.0.0` 仅关联到 npm dist-tag `maintenance-1`。
- 发布工作流必须校验标签来源分支和包版本；普通 `v*.*.*` 标签继续只允许来自 master 并发布到 `latest`。
- 更新根 `README.md`，明确普通安装、维护通道安装、升级方式以及 `mbs update` 只跟随 `latest` 的限制。
- 保留旧远程功能分支，不删除、不覆盖、不强制推送。
- 本任务不修改 npm `latest`、不创建面向 master 的 PR、不修改或合并 master。

## 受影响范围

- `packages/cli/package.json`
- `.github/workflows/ci.yml`
- `.github/workflows/release.yml`
- `scripts/test-release-workflow.mjs`
- `README.md`
- 本任务审计文档、审计索引和项目记忆
- 本地与远程 Git 分支、维护发布标签和 npm `maintenance-1` dist-tag

## 输入与输出

- 输入：当前已提交且工作区干净的功能分支 `20260722-FEATURE-接口检索降噪`。
- 输出：同一提交历史上的本地与远程 `1.0.0` 分支、维护发布标签 `maintenance-1-v1.0.0`，以及 npm `maintenance-1` 指向的 `@mb-it-org/cli@1.0.0`。
- 不变项：业务代码、manifest、接口命令、认证配置、数据、master、既有远程分支和 npm `latest`（发布前基线为 `0.1.58`）。

## 验收标准

1. 当前本地分支名称为 `1.0.0`，上游为 `origin/1.0.0`。
2. `packages/cli/package.json` 的版本为 `1.0.0`，其他 workspace 包版本不被批量修改。
3. CI 同时覆盖 master 和 `1.0.0`，既有构建与测试步骤不变。
4. 全 workspace 构建、测试、发布保护测试和代表性命令帮助验证通过。
5. 提交只包含本任务范围文件，不混入凭据、生成产物或无关修改。
6. `origin/1.0.0` 指向本次提交；旧远程功能分支和 master 未修改。
7. `maintenance-1-v1.0.0` 只能从 `1.0.0` 分支当前历史触发，普通 `v*.*.*` 标签仍只允许来自 master。
8. npm 中 `@mb-it-org/cli@1.0.0` 发布成功，`maintenance-1` 指向 `1.0.0`，`latest` 保持发布前的 `0.1.58`。
9. README 明确普通用户仍安装 `latest`，维护用户显式安装 `@maintenance-1`，且维护用户不得使用只跟随 `latest` 的 `mbs update`。
10. 发布包通过现有 deploy bundle、安装性和命令验证，不允许直接从带 `workspace:*` 的 `packages/cli` 发布。
