## 故障现象

`mbs database query` 收到后端非 2xx HTTP 响应时，没有输出后端错误 body，而是报 `TypeError: Converting circular structure to JSON`，循环从 Node `Socket`、`ClientRequest` 和 `Agent` 形成。

## 根因分析

- `database query` 使用 Axios `responseType: stream` 保持成功 NDJSON 流式输出。
- 非 2xx 响应也以 Node `IncomingMessage` 流进入共享 rejection interceptor；现有代码把 `error.response.data` 直接保存为 `BackendResponseSnapshot.body`。
- 命令错误出口按既有“后端 body 原样透传”契约对非文本值执行 JSON 序列化，因此误序列化含 Socket 循环引用的响应流。
- 普通非流式 POST 的错误 body 已被 Axios 解析为对象，不受影响；成功 NDJSON 流也能正常逐块读取。
- 该故障不是 CLI 重新添加 `{ok,data,error}` envelope。只有没有后端 body 的本地错误继续使用 CLI 自有安全错误结构。

## 修复预期

1. 非 2xx 流式响应必须先在共享 HTTP 边界内有界读取，并按 JSON 或文本恢复为可输出的后端 body。
2. 后端 body 继续直接透传，不增加 CLI envelope；HTTP 状态、401/403 分类、一次认证刷新和退出码保持不变。
3. 成功 NDJSON 继续流式直通，不因错误路径修复而缓冲完整查询结果。
4. 异常读取、超限和纯网络失败必须释放响应流并使用安全本地错误，不得再次序列化网络对象。
5. 使用真实 Node HTTP adapter 的回归测试覆盖流式非 2xx JSON、文本和认证重试边界。
6. 定向测试、共享包回归、全仓测试与构建通过后，将本机活动 `mbs` link 到工作区并完成离线冒烟。

## 验收标准

1. 原最小复现不再产生循环引用异常，错误快照只携带 JSON、文本或安全本地错误。
2. HTTP 422 JSON body 与纯文本 body 均可透传并保留退出失败语义。
3. 流式 HTTP 401 仍只刷新一次；最终失败保留解析后的后端 body。
4. 成功 NDJSON 行为无回归。
5. 全仓测试、构建、差异与敏感信息检查通过。
6. 本机活动包精确指向工作区 `packages/cli`，版本、database help、Skill 和共享依赖目标核验通过。

## 风险与回滚

- 错误流读取设置固定大小上限，避免错误响应导致无界内存增长；超限时销毁响应流并返回本地安全错误。
- 解析只作用于非 2xx 错误流；成功数据流保持原有背压与内存特征。
- 代码回滚为普通反向修改；已发布版本不可覆盖，如需修正应发布更高补丁并按需回退 dist-tag。
- 本任务已获当前修复的 Git 暂存与本地提交授权；不推送、不发布 npm，远程写入仍需另行明确授权。
