# 需求描述：发布 1.1.2 维护版本

> 安全提示：本文不得记录账号、密码、Cookie、Token、真实请求正文、生产响应、签名地址或未脱敏发布日志。

## 任务属性

- 级别：L3（认证行为、Git 远程写入和 npm 生产发布）
- 类型：RELEASE / SECURITY
- 任务状态：已完成
- 执行授权：已授权
- 授权来源：用户明确要求“提交代码并发布npm版本1.1.2”
- 交付状态：已发布
- 关联修复：`20260904-[BUG]刷新交换移除客户端类型头`

## 背景

`1.0.0` 长期维护分支已在 npm `maintenance-1=1.1.1` 基线上完成兼容会话交换请求头修正：登录型 Refresh Cookie 与管理型 LongToken 两类刷新调用均不再发送 `client-type: cli`。本地 V3 和本机链接安装已经验证，用户要求提交当前修复并发布 `1.1.2`。

## 目标

1. 审查并提交当前工作区中属于该认证修复、本机替换审计和发布审计的改动。
2. 将 `@mb-it-org/cli` 从 `1.1.1` 升级到未占用的 `1.1.2`。
3. 普通推送到 `origin/1.0.0`，等待分支 CI 成功。
4. 创建并推送 `maintenance-1-v1.1.2`，通过既有 Release 工作流发布 npm `maintenance-1`。
5. 发布后核验精确版本、dist-tag、官方源安装包和 Skill；保持 `latest=0.1.59` 不变。

## 发布内容

- compat-session 在首次 LongToken 登录、登录型 Cookie Refresh 和管理型 LongToken Refresh 下均不发送 `client-type: cli`。
- 密码登录和 current-user 查询继续不发送该头。
- 普通业务 APIClient 继续发送既有 `client-type: cli`。
- Cookie 轮换、长期凭据互斥、Access Token 仅内存、失败关闭和远程 HTTP 风险边界保持不变。

## 范围与安全边界

- 目标仅为 `origin/1.0.0`、标签 `maintenance-1-v1.1.2` 和 npm `maintenance-1`。
- 不修改或推送 `master`，不创建 `v1.1.2`，不移动 npm `latest`。
- 不强推、不删除远程引用、不覆盖或删除已发布 npm 版本。
- 不读取、重放、记录或提交任何真实凭据；真实登录不作为发布自动化输入。
- 发布失败时停止在可恢复状态；npm 版本不可覆盖，缺陷通过更高补丁版本修复。

## 输入与输出

- 输入：当前已验证的认证修复工作区、版本 `1.1.2` 和既有维护发布工作流。
- 输出：修复提交与版本提交进入 `origin/1.0.0`，npm 官方源发布 `@mb-it-org/cli@1.1.2` 并将 `maintenance-1` 指向该版本。

## 验收标准

1. 暂存差异完整且只包含当前修复、关联审计、版本和发布审计，不含真实凭据、占位实现或无关产物。
2. frozen install、全仓测试构建、发布保护、CLI 冒烟、差异和敏感信息检查通过。
3. 功能提交和版本提交均普通推送到 `origin/1.0.0`，对应分支 CI 成功。
4. 维护标签精确指向版本提交，Release 工作流成功发布 npm。
5. npm 官方源存在 `1.1.2`，`maintenance-1=1.1.2`，`latest=0.1.59`。
6. 官方源隔离执行验证版本、登录与刷新帮助、主 Skill 和更新 Skill；随后回填任务与项目记忆。

## 回滚与观察

- 标签推送前通过普通修复提交纠正问题，禁止改写已推送历史。
- npm 发布后不能覆盖同版本；严重缺陷使用更高补丁版本，dist-tag 回调需要新的明确授权。
- 观察分支 CI、Release 作业、npm 精确版本、dist-tags 和官方源临时安装结果。
