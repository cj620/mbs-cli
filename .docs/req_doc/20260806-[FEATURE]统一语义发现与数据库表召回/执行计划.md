## 2. 类型与契约

- [已实现] `FindResult` 已扩展为 workflow/api/table 判别联合类型，共享字段保持最小化。
- [已实现] table 稳定键、host、database、schema、tableName 使用独立的长度、字符和一致性校验，不套用 API 命令正则。
- [已实现] `nextAction` 只允许 `database.show-create-table`，参数逐字段验证且必须与 table 身份一致；后端命令字符串被忽略。
- [已实现] 未知类型、重复身份、非有限分数、超过 50 条数组和非法控制字符失败默认拒绝。
- [已实现] CLI 请求声明 `table-actions-v1`；后端据此只向支持版本返回 table。

## 3. find 与执行路径

- [已实现] `mbs find` 默认 `all`，用户只提供自然语言，CLI 保留后端融合顺序输出混合候选。
- [已实现] API 路径保持 `find → describe → command --help → execute`，命令仍由本地安全标识派生。
- [已实现] table 候选衔接既有 `database show-create-table` 参数；用户确认表结构和查询目标后再进入 `database query`，CLI 不自动执行。
- [已实现] workflow 步骤继续使用 find，主 Skill 不向最终用户询问目标类型。
- [部分实现] CLI 保留后端 `AMBIGUOUS` 提示且不自动选择；口径、时效和成本的专门解释仍取决于后端权威元数据。

## 5. 安全与隐私

- [已实现] table 标识只作为结构化字段输出，由 Skill 逐参数交给 oclif；CLI 不执行后端字符串。
- [已实现] diagnostics 仍只输出固定失败分类，不输出响应、DDL、SQL、Cookie 或 URL。

## 8. 风险与回滚

- 后端提前返回 table 会使旧 CLI 契约失败；发布顺序和能力协商必须先完成。
- table 参数处理错误可能形成命令注入或访问错误数据源；必须使用结构化参数和既有后端鉴权。
- 回滚时关闭后端 table 能力即可恢复 workflow/api；不得恢复本地接口或表卡片降级。
- 本地 CLI、测试、Skill 源文件与文档已获授权并完成首轮实现；全局安装、发布和真实服务端联调仍未授权。
