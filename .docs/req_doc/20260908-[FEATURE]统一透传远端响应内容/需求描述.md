## 背景与问题

`MBSCommand` 驱动的普通业务查询已直接输出后端 response body，但 `find`、`describe` 和 `serve` 仍保留独立包装或归一化逻辑。语义发现接口返回权限错误时，`find` 把实际后端 body 替换为固定的 `semantic-discovery` 错误，导致调用者看不到真正的失败原因。

## 用户决定

禁止对直接暴露给调用者的接口或命令实际返回内容增加包装、裁剪、字段映射、重排、补充元数据或替换错误。远端 response body 是不可变载荷。

## 范围

- `mbs find`：成功时输出召回接口 body；后端业务或 HTTP 错误时输出错误携带的原始 body。
- `mbs describe`：成功时输出详情接口 body；后端业务或 HTTP 错误时输出错误携带的原始 body。
- `mbs serve` 的 manifest、project API 与 `/proxy/*` 远端路由：成功与具有上游 body 的错误均直接发送该 body。
- 普通业务命令和 `mbs request`：保持既有后端 body 透传契约。
- `find`/`describe` 的本地参数校验、无响应的超时/网络/配置/认证初始化失败，以及 `serve` 本地管理端点：因不存在上游 body，可继续使用 CLI 自有结构。

## 保留的控制语义

- 共享 HTTP 客户端可读取 HTTP 状态和既有业务码，以维持一次认证刷新、权限分类与进程退出码；不得因此改写最终输出 body。
- `request --api-id` 可内部校验详情元数据以安全构造只读请求；该内部元数据不是该命令直接返回给调用者的业务结果。
- NDJSON 保持原流直通，不缓冲、不包装。

## 不在范围

- 不取消认证刷新、只读 method 限制、请求参数校验或 serve 回环地址安全边界。
- 不把本地命令（登录、退出、配置、skills、路由发现、启动状态）伪装成远端响应。
- 不发布 npm 包，不执行远程写入，不处理下游应用迁移。

## 验收标准

1. 对 JSON、文本、标量和 `null` 成功 body，不增加 `{ok,data}` 或 `meta`，不提取内层 `data`。
2. 对带 `backendResponse` 的认证、权限、业务或 HTTP 错误，输出其 body，不替换为固定错误。
3. `find` 不再归一化、截断、重排或派生召回候选字段；发送到后端的请求校验和 `topK` 参数保持。
4. `describe` 命令输出原始详情 body；`request --api-id` 的内部安全元数据校验保持。
5. `serve` 远端路由同时保留上游 body 与可用的上游 HTTP 状态；本地产生的错误仍使用安全结构。
6. 定向测试、全量测试和构建通过；文档、决策、记忆和实际代码一致。

## 风险与回滚

- 这是输出契约变更，下游若读取旧的 `ok/data/error/meta` 外层需要同步迁移。
- 原样暴露的远端内容必须始终作为数据，不得把返回的命令文本视为执行授权。
- 回滚时恢复 `find`/`describe`/`serve` 的旧包装测试与实现，同时撤销本任务对 DEC-002 的扩展说明。
