# 发布 1.0.4 维护版本需求描述

> 安全提示：本文档不得记录凭据、Cookie、真实请求正文、上传内容、生产响应、签名地址或未脱敏发布日志。

## 背景

npm `maintenance-1=1.0.3` 尚不支持 cli-service 已确认的完整请求体编码契约。当前 `1.0.0` 长期维护分支工作区已经完成接口请求体编码端到端实现与本地 V3：动态 `request --api-id`、共享编码器、manifest 生成、本地 serve、Skill、README 和自动化测试均已更新。用户现明确要求提交当前代码并发布 `1.0.4`。

## 目标

- 将 `@mb-it-org/cli` 从 `1.0.3` 升级到未占用的 `1.0.4`。
- 精确提交接口请求体编码功能、配套测试/文档和本发布审计，普通推送到 `origin/1.0.0`。
- 维护分支 CI 成功后创建轻量标签 `maintenance-1-v1.0.4`，触发既有 Release 工作流发布 npm `maintenance-1`。
- 发布后确认 `maintenance-1=1.0.4`，同时保持发布前普通通道 `latest=0.1.59` 不变。
- 从 npm 官方源核验实际发布包版本、公开命令入口和请求体编码产物。

## 发布内容

1. `mbs request --api-id` 使用 cli-service 权威详情校验 method/path 并编码 `NONE/JSON/FORM_URLENCODED/MULTIPART/TEXT/XML/BINARY`。
2. 共享请求体编码器处理嵌套表单、multipart 普通值/文件/Base64、受控 Content-Type、文件名策略、有界文件读取和失败关闭。
3. manifest 归一化、生成命令与本地 serve 消费统一请求体元数据；旧 manifest 与旧 JSON 调用保持兼容。
4. CLI 详情、动态请求、serve、共享 HTTP、生成器和 Skill/README 的测试与文档同步更新。

## 范围边界

- 只处理 `1.0.0` 长期维护分支和 npm `maintenance-1` 通道。
- 不修改、合并或推送 `master`，不更新 npm `latest`。
- 不强推、不删除远程引用、不覆盖任何已发布 npm 版本。
- 排除用户本地 `.idea/claudeCodeTabState.xml` 修改；保留该文件本地内容且不提交。
- 不发送真实业务请求，不读取或记录凭据、Cookie、上传内容、文件路径和生产响应。
- 本次不修改 cli-service、pms-front、认证、网关权限、数据库或生产配置。

## 验收标准

- frozen install、manifest dry-run、全工作区构建、全量测试、发布保护、代表性 CLI 帮助、差异与敏感信息检查通过。
- 发布提交只包含已确认范围，属于 `origin/1.0.0`，对应分支 CI 成功。
- `maintenance-1-v1.0.4` 指向已通过 CI 的维护分支提交，Release 工作流成功。
- npm 官方源存在精确版本 `1.0.4`，dist-tag 为 `maintenance-1=1.0.4` 且 `latest=0.1.59`。
- 隔离安装官方包后版本、`request --help`、Skill 入口和已编译请求体编码能力通过只读核验。
