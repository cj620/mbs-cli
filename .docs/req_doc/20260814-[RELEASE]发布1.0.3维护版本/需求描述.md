# 发布 1.0.3 维护版本需求描述

## 背景

npm `maintenance-1=1.0.2` 已发布，但其 find/describe 将网关顺序拼成 `/cli/gateway`；另有 13 条源 manifest action 重复携带 `/gateway`。当前 `1.0.0` 分支已把正式 HTTP 请求统一为 `<apiUrl>/gateway/cli/<service>/...`，并完成本地修复验证。

## 目标

- 将 `@mb-it-org/cli` 从 `1.0.2` 升级到尚未占用的 `1.0.3`。
- 精确提交当前网关路由修复并普通推送到 `origin/1.0.0`。
- 分支 CI 成功后创建轻量标签 `maintenance-1-v1.0.3`，由既有 Release 工作流发布 npm。
- 发布后确认 `maintenance-1=1.0.3`，同时 `latest` 保持 `0.1.58`。
- 从 npm 官方源核验实际发布包版本、命令入口及已编译的 find/describe 路由。

## 发布内容

1. find 使用 `/gateway/cli/cli-service/cli/api/recall`。
2. describe 使用 `/gateway/cli/cli-service/cli/api/recall/detail`。
3. 13 条源 manifest action 去掉重复的 `/gateway`，生成业务命令统一经 `/gateway/cli/<service>/...` 请求。
4. 重新生成依赖整份 manifest hash 的业务包与 Skill 文件，保证源 manifest 与生成产物一致。

## 范围边界

- 只处理 `1.0.0` 长期维护分支和 npm `maintenance-1` 通道。
- 不修改、合并或推送 master，不更新 npm `latest`。
- 不强推、不删除远程引用、不覆盖任何已发布 npm 版本。
- 排除用户本地 `.idea/claudeCodeTabState.xml` 修改。
- 不修改 serve 上游语义，不发送真实业务请求，不读取、记录或提交 Cookie 与生产响应。

## 验收标准

- frozen install、生成稳定性、构建、全量测试、发布保护和代表性 CLI 帮助均通过。
- 发布提交属于 `origin/1.0.0`，对应分支 CI 成功。
- Release 工作流成功，npm 官方源存在精确版本 `1.0.3`。
- npm dist-tag 为 `maintenance-1=1.0.3`、`latest=0.1.58`。
- 官方源安装包显示版本 `1.0.3`，并包含正确的 find/describe 路由及生成业务路径。

用户于 2026-08-14 明确要求“提交代码并发布1.0.3”，授权当前范围内的版本升级、提交、普通推送、维护标签和 npm 维护通道发布。
