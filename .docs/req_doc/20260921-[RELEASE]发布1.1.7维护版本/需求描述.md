> 安全提示：本文不得记录 npm/GitHub 凭据、认证缓存、内部地址、生产 SQL、真实业务响应或未脱敏日志。

## 任务属性

- **级别 / 类型**：L3 / RELEASE
- **任务状态**：执行中
- **交付状态**：未交付
- **记忆键**：`RELEASE-LINE-1X`、`CLI-RESPONSE-PASSTHROUGH`
- **发布分支**：`1.0.0`
- **目标版本**：`@mb-it-org/cli@1.1.7`
- **目标标签**：`maintenance-1-v1.1.7`

## 发布目标

将提交 `89e1ab2` 中的流式 HTTP 错误响应序列化修复升级为 npm `1.1.7`：非 2xx 流式响应在共享 HTTP 边界内有界读取为 JSON 或文本，再按既有状态分类并直接透传后端 body；成功 NDJSON、一次认证刷新和退出码契约保持不变。

## 发布边界

- 只发布当前 `1.0.0` 维护线中已经提交、验证并归档的修复及必要版本、发布文档。
- `maintenance-1-v1.1.7` 触发维护发布；成功后将当前已与维护线对齐的 `latest` 从 `1.1.6` 提升为 `1.1.7`。
- 不覆盖 npm `1.1.6`，不强推、不改写历史、不删除或重建远程标签。
- 不执行真实 MBS 查询，不读取或输出认证缓存、Token、Cookie、数据库凭据或业务响应正文。
- 任一发布门禁、分支 CI、Release、registry 或官方包验证失败时停止后续远程动作。

## 发布前事实

- 本地 `1.0.0` 比 `origin/1.0.0` 领先修复提交 `89e1ab2`，工作区干净。
- CLI 当前版本为 `1.1.6`；目标 Git 标签和 npm `1.1.7` 均不存在。
- npm 官方源当前为 `maintenance-1=latest=1.1.6`；本机 npm 未登录，发布依赖仓库 Release workflow。
- PATH 首项的系统级 `1.1.6` 是普通旧安装，不含修复；工作区构建已通过合成错误回归。

## 发布进度

- 修复提交 `89e1ab2` 已普通推送到 `origin/1.0.0`，分支 CI run `35569170441` 成功。
- 当前进入 `1.1.7` 版本提交阶段；发布标签和 npm 版本尚未创建。

## 验收标准

1. frozen install、327 条全仓测试、14 个 workspace 构建、生成与发布守卫、打包内容及敏感检查通过。
2. 修复提交普通推送到 `origin/1.0.0` 且分支 CI 成功。
3. CLI 版本精确更新为 `1.1.7`，版本提交普通推送且分支 CI 成功。
4. 标签唯一、精确指向版本提交并属于远端 `1.0.0` 历史；Release workflow 成功。
5. npm 官方源存在 `1.1.7`，最终 `maintenance-1=latest=1.1.7`。
6. 官方源隔离安装的版本、database query help、database Skill 及流式错误回归通过。
7. 发布记录、原 Bug 任务、审计索引和项目记忆与实际状态一致；最终工作区干净且分支与远端同步。

## 风险与回滚

- npm 版本不可覆盖；发布后如发现问题，以更高补丁版本修复，并可将 dist-tag 恢复到已核验的 `1.1.6`。
- 标签发布失败时保留标签和失败证据，修复流程后重跑；不得用不同内容重建同版本。
- `latest` 提升只在精确版本发布和官方包验证成功后执行；失败时不影响已发布的 `maintenance-1` 包，但任务保持未完成或待验收。
- 系统级旧安装的替换不作为发布成功证据；最终使用官方源隔离安装验证，不读取真实凭据。
