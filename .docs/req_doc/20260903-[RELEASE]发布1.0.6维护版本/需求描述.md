# 发布 1.0.6 维护版本需求描述

> 安全提示：本文档不得记录账号、密码、Cookie、Token、真实请求正文、生产响应、签名地址或未脱敏发布日志。

## 背景

npm `maintenance-1=1.0.5` 已发布且不可覆盖。当前 `1.0.0` 长期维护分支工作区已完成 MBS 认证边界整改：禁止接触或持久化 `MBS_KEY`，支持扫码、账号密码和后台管理型长期 Refresh Token 登录，统一通过 compat-session 交换短期 Access Token 与兼容 `SESSION`，并在重新登录或切换用户前清空旧认证缓存。用户明确要求提交这些代码并发布 `1.0.6`。

## 目标

- 将 `@mb-it-org/cli` 从 `1.0.5` 升级到未占用的 `1.0.6`。
- 精确提交本轮认证实现、测试、文档和发布审计，排除用户的 `.idea/claudeCodeTabState.xml` 修改。
- 普通推送到 `origin/1.0.0`，等待对应分支 CI 成功。
- 创建并推送轻量标签 `maintenance-1-v1.0.6`，触发现有 Release 工作流发布 npm `maintenance-1`。
- 发布后确认精确版本与 dist-tag，并从 npm 官方源隔离安装验证实际产物。

## 发布内容

1. CLI 不再读取、捕获、缓存或持久化可解析账号密码材料的 `MBS_KEY`，旧 key 位置只执行删除式兼容。
2. `mbs login` 支持扫码、终端账号密码和隐藏输入管理型长期 Refresh Token；非扫码方式不启动浏览器。
3. 登录型 `AUTH_REFRESH` 与管理型 `LongToken` 严格互斥缓存；短期 Access Token 只存在于当前进程内存。
4. `mbs refresh` 和业务请求首次认证失败统一调用 `/gateway/auth-center-service/auth/token/exchange/compat-session`，最多刷新并重试一次。
5. 每次有效执行 `mbs login` 都在任何新登录交互前清空旧 `SESSION`、Refresh 凭据、到期时间和用户摘要；失败或取消不恢复旧登录态。

## 范围边界

- 只处理 `1.0.0` 长期维护分支和 npm `maintenance-1` 通道。
- 不修改、合并或推送 `master`，不更新 npm `latest`。
- 不强推、不删除远程引用、不覆盖任何已发布 npm 版本。
- 保留 `.idea/claudeCodeTabState.xml` 当前内容和暂存状态，不将其提交。
- 不读取真实凭据，不发起真实登录或业务请求，不把 Cookie、Token 或响应正文写入审计证据。

## 验收标准

- frozen install、全工作区构建和测试、发布保护、CLI 帮助、差异及敏感信息检查通过。
- 发布提交只包含当前认证与发布范围，且属于 `origin/1.0.0`；分支 CI 成功。
- `maintenance-1-v1.0.6` 指向已通过 CI 的维护分支提交，Release 工作流成功。
- npm 官方源存在精确版本 `1.0.6`，`maintenance-1=1.0.6`，发布前的 `latest=0.1.59` 保持不变。
- 官方源隔离安装后版本、登录帮助和认证相关编译产物存在性通过核验。
