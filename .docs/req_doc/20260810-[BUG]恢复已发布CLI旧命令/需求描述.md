# 恢复已发布 CLI 旧命令

> 安全提示：本文档禁止写入凭据、真实用户数据、未脱敏日志、请求响应正文和敏感生产证据。

## 背景

npm 正式版 `@mb-it-org/cli@0.1.58` 已向用户提供五个业务命令。当前大规模 manifest 改造删除或重命名了这些公开命令，依赖命令标识、参数和请求行为的脚本可能在升级后中断。

## 故障现象

当前工作区无法发现以下已发布命令：

- `mbs crm crm-web-service-get-amazon-acc-health-info`
- `mbs product erp-monitor-hot-product-all-listing`
- `mbs product erp-product-product`
- `mbs pim instudio-pms-get-shop-manager-ranking-list`
- `mbs pim instudio-pms-list`

其中 `mbs pim instudio-pms-list` 对应接口仍由新命令 `mbs pim instudio-pms-list-sku-manager` 提供，但旧命令标识已丢失；其余四个接口未进入当前生成 manifest。

## 根因分析

生成器根据当前 audit manifest 重建业务插件并移除不再出现的生成模块；命令名还会根据同名接口冲突动态消歧。已发布命令缺少独立于当前 manifest 的兼容入口，因此 manifest 扩容或删减会改变公开命令集合。

## 修复预期

增加一个不受 manifest 清理影响的人工维护兼容插件，按 `0.1.58` 已发布契约恢复五个命令。兼容命令必须保留原命令标识、说明、flag 名称、flag 类型、必填性、查询类 HTTP 方法、接口路径、数组转换和结构化输出行为。

## 业务边界

- 只恢复五个 CLI 命令，不恢复 `mbs serve --project-apis` 的旧 HTTP 路由。
- 不改变现有新命令，不删除或重命名任何当前命令。
- 不修改后端，不调用生产业务接口，不发布 npm 包。
- 只允许原有只读 `GET` 和查询类 `POST`。

## 受影响范围

- 新增人工维护的兼容业务插件。
- CLI 插件注册与 workspace 锁文件。
- 五个兼容命令的契约回归测试。
- 本任务审计索引与待生效项目记忆。

## 输入与输出

- 输入：与 `@mb-it-org/cli@0.1.58` 相同的命令名称和 flags。
- 输出：继续使用 `MBSCommand` 的 `{ "ok": true, "data": ... }` 成功结构及既有错误/退出码契约。
- 上游请求：保持 `0.1.58` 的方法、路径、字段名和逗号分隔数组转换。

## 验收标准

1. 五个旧命令均可由本地 CLI 发现并显示帮助。
2. 五个命令的 flag 名称、类型、必填性和布尔反向 flag 行为与 `0.1.58` 一致。
3. 五个命令分别调用原 GET/POST 路径，POST 请求字段及数组转换与旧版一致。
4. 兼容插件不带 `.mbs-generated.json`，manifest 生成器不会把它作为过期生成模块删除。
5. 定向测试、兼容插件测试、CLI 构建和五条 `--help` 验证通过。
6. 不覆盖或混入工作区已有的无关修改，不执行暂存、提交、推送或发布。
