# 修复 Skill 接受 COMPUTE

> 安全提示：不记录凭据、真实业务数据、请求响应原文或生产证据；测试仅使用人工样本。

## 故障、根因与预期

- 【故障现象】后端召回及修复后的详情接受 QUERY/COMPUTE，但项目 Skill 只允许 QUERY；`request --api-id` 的解析器也拒绝 COMPUTE。
- 【根因分析】生成器的主/域协议、手工全局参考、参数依赖协议、`ApiDetailData` 类型与 `normalizeApiDetailResponse` 仍限定 QUERY。`describe` 命令的 `fetchApiDetail` 已透传原始响应，不需要改写。
- 【修复预期】项目 Skill 与动态请求详情解析均接受 QUERY 或 COMPUTE（只读计算统计），保留真实类型、GET/POST、字段与编码校验。

## 边界

修改项目生成源、相关手工 Skill 参考、详情解析类型与回归测试，重新生成根/7 个域 Skill 并通过现有构建同步打包副本。不手工修改生成文件。不改变 manifest/生成业务命令、认证、路径限制、响应透传、依赖、版本、全局安装或宿主个人 Skill。

历史 DEC-001 的 QUERY 单类型限制依据用户当前明确决定在本任务内部分修正；不扩大为 CREATE/UPDATE/DELETE/OTHER。聚合根归档，因为跨生成器、共享协议与 CLI 消费者。

## 验收

1. 主 Skill、域 Skill、全局参考和来源 API 参数依赖协议接受 QUERY/COMPUTE，仍要求 GET/POST 和只读性质。
2. COMPUTE 可经 `describeApi` 读取并进入元数据编码，真实类型、字段树及编码元数据保留；其他、空或未知类型拒绝。
3. 原始响应透传、错误/超时、ID、危险路径、写入 method 和 GET body 拒绝行为保持。
4. 源模板生成稳定，构建副本一致，定向测试、全仓测试、构建和无网络 Skill/帮助冒烟通过。

不以本地成功推定已发布；真实 `find → describe → request` 联调待目标环境与正常登录态，不执行真实业务调用。
